# Parallax collaboration contract

Parallax is an original Rainmeter suite inspired by the utility density of ModernGadgets. Do not copy its code or assets without reviewing its license and recording attribution.

Read `docs/ARCHITECTURE.md` and the revised `docs/APPEARANCE.md` before editing. Development now happens directly in Claude in a single session, not through separate per-module Codex tasks — the historical task split in `docs/TASKS.md` is a record of the initial build, not a live process. The module ownership below is still a useful file-organization convention (it keeps each utility's source, resources and docs together), but it is no longer an enforced boundary between isolated agents: touch shared settings, styles, geometry or another module's files directly when a change calls for it, and note the change in the relevant doc(s) rather than filing a handoff.

Each utility owns `Skins/Parallax/<Module>/`, `Skins/Parallax/@Resources/Modules/<Module>/`, `Skins/Parallax/@Resources/User/<Module>.inc`, and `docs/modules/<Module>.md`. Module names: Chronometer, CPU, RAM, GPU, IO, Network, Media, Visualizer. IO owns disk activity; Network owns NIC traffic. Shared tooling is in `tools/` and `packaging/`.

Maintain a Dependencies section in each utility's module document whenever an implementation changes its runtime, plugin, helper, service or asset requirements. Distinguish required, bundled and optional components; record the enabled feature, setup or version constraints actually known, and behavior when unavailable. Planned integrations are not installed dependencies. Keep the shared requirements and utility index in `docs/DEPENDENCIES.md`, plus the Global Settings and ColorPicker dependency sections in their respective documents, up to date whenever any module's dependencies change.

Use built-in measures first. Optional plugins/providers must be explicit and show honest missing/unsupported states. No fabricated telemetry. No repeated shell/process launches for polling. No credentials, machine-specific sensor IDs, binary downloads, or user data in distribution. Do not install dependencies, change the user's live Rainmeter configuration, or publish releases as part of initial implementation.

Explicit user-approved exception, 2026-09-11: the global integration task may download and bundle unmodified IBM Plex Sans fonts from IBM's official repository with the SIL Open Font License. This is skin-local font bundling, not system-wide font installation. Module tasks inherit FontFace and do not provision fonts independently.

Validate feasible behavior, not just file existence — but scale the check to the size of the change. A routine edit needs a quick, targeted check that demonstrates it works, not a full multi-scale/multi-config sweep. Save broad, exhaustive validation (every scale, every layout, large assertion counts) for pre-release acceptance passes, not day-to-day iteration. A large assertion count is not itself evidence of quality; do not run redundant sweeps just to report a bigger number. Record checks and runtime limitations honestly, including what remains unverified — an honest "unverified for now" is acceptable mid-development and is not a blocker to moving on. Completion of a module prototype is not proof of performance or release readiness.
