# Native Chronometer settings smoke

Run from the repository root using the existing Rainmeter installation:

```powershell
& '.\Skins\Parallax\@Resources\Modules\Chronometer\Tests\SettingsSmoke\Run-Smoke.ps1' -ColumnWidths 180 -Columns 1 -Scales 0.75
```

Optional `-TitleFontSize 12 -HeaderFontSize 10 -FontSize 10` and `-BorderThickness 4 -DividerThickness 4` override only the copied global settings. The lifecycle fixture starts with all four sections shown. It toggles every section off and back on through the production settings meters, verifies saved flags and Shown/Hidden readouts, and asks the refreshed countdown's test measure to verify actual compact height and visible/hidden dimensions. At every toggle, it also checks the settings menu's collapsed details, exact reflow and remaining controls. An existing event's exact saved bytes, every unrelated saved option and the unchanged running timer's deadline must survive every toggle. The default timeout remains 30 seconds.

The test stages the production countdown and settings subconfig, backend scripts, shared resources (including `UtilitySettingsNote.inc` and `Scripts/SettingsInput.ps1`) and existing bundled fonts in its own unique `SettingsSmoke/.runtime/run-<guid>/` directory. The shared utility note and Global Settings link join the existing all-meter bounds check. The menu's `PanelHeight` formula must equal 752 logical px minus 84 for hidden Clock details, 28 for hidden Event details and 216 for hidden Timers details; Uptime has no dependent detail rows. Only copied settings are changed: the clock starts in 24-hour format, and the first two timers have known 1500/300-second durations. A test Script measure is appended to each copied skin. The copied settings menu's initial `Update=-1` is replaced in place with `Update=1000` for test orchestration; the production menu remains driven by clicks.

The form checks cover 15 fields with a separate 112 px label column and at least 28 px pitch. Nine selectors use shared steppers: width, clock format, date format, list, adjustment step and four timer durations. Their 18 px Accent 1 arrows flank a bordered center with 2 px gaps; centered values use body text color and size. Boolean fields and event configuration retain their existing compact padded fields. Frame, label and center must dispatch the same production action; arrows retain distinct backward/forward commands. All labels, arrows, frames, values and adjacent rows must have separate hit areas. Section dividers retain `StyleRule`, with clearance from headings and first fields.

Collapsed sections keep their headings and visibility fields accessible. All five headings must use Accent 1 and the shared header font size. The 47 dependent meters must hide with their owner, have zero native dimensions and reset their raw Y anchor to Inset so they cannot keep the window tall. Visible fields, later headings and the footer must move by exactly the removed detail height. After reaching all-hidden, the harness refreshes only the isolated settings menu and verifies its initial 424 px collapsed layout before restoring the sections. A small fixture continuation file retains the check count and original timer deadline across that refresh; an unrelated-options baseline excludes only the four visibility keys. The same lifecycle then restores and rechecks the 19 text probes.

Native checks dispatch the production gear action to open the menu and inspect every actual menu meter's rectangle, panel dimensions, gutters and populated readouts. With two timers running, the test dispatches the menu's actual clock, duration-plus and width actions. It verifies the literal `%I:%M:%S %p` format survives `!WriteKeyValue`, the clock renders it after refresh, the duration increases by the selected 60-second step and resets only that timer, and the other timer keeps its exact saved deadline through every refresh. The width setting changes the countdown while the open settings menu remains two pitches wide. The actual Global Settings link activates a harmless, test-only `Parallax\Settings` target in this isolated SkinPath; the stub records activation and immediately deactivates itself. The real Global Settings implementation is not staged, and copied global preferences must remain byte-for-byte unchanged. Finally, the actual close action deactivates only the menu; the countdown remains loaded and continues advancing. Saved isolated Rainmeter.ini active states for the countdown, menu and navigation stub are checked after exit.

Add `-NumberInput` for the bounded typed-entry integration scenario; only that scenario permits a timeout up to 60 seconds and defaults to 60 rather than the standard 30. Its isolated helper copy reads a fixed fixture choice and selects the shared helper's existing ValidateOnly or Cancel mode, so no numeric input window opens. Production launch arguments, duration bounds, stdout protocol and FinishAction remain unchanged. Timer 3 starts at 600 seconds. Three real center actions validate/save 1599, reject 604801 and cancel; they must produce exactly three helper launches. The successful response must reach both the saved option and actual timer snapshot. Invalid/cancel responses must write no settings bytes, and every response preserves the other running timer's deadline. The unrelated-options baseline is captured after this sequence so the subsequent visibility audit retains the accepted edit. At all-hidden, direct attempts to dispatch the Step/duration center actions must launch nothing and write nothing. This verifies process/protocol integration; physical typing, focus, Enter/Escape and overlay pixels are outside this harness.

The event adapter is staged with the other production Lua files. This lifecycle fixture creates an isolated future event named `Visibility event` using production `EventCore.encode`, records its exact bytes and explicitly reloads it. Its bytes remain unchanged through every section toggle and settings refresh; the final countdown still shows the saved name. The earlier 408-check run instead covered an initially unset event and verified that unrelated settings controls created no event file. The event configuration button is checked for native bounds with the other menu meters, but its action is never dispatched. This harness does not open the event editor or exercise its GUI Save/Cancel behavior.

The event assertion expects the label `Countdown to Visibility event:` and a separate compact value such as `5d 3h 20m 10s`. Both final compact-form lifecycle cases verified this display after section toggles and settings refreshes.

A baseline file outside the refreshed countdown skin prevents test state from resetting when a production setting refreshes the module. The native snapshot store supplies the deadline assertions. The test sends no unqualified CLI bangs and never changes the live Rainmeter configuration. Each instance is launched with an existing, absolute isolated SkinPath and its own INI file. Only the returned process can be stopped on timeout. Generated directory paths are verified before recursive cleanup. Both skins use zero opacity; no downloads or dependency installation occur.

Nineteen native text probes cover the menu title, visibility button, column count, clock/date choices, duration step, seven-day duration, saved-status text and all eleven static form labels using their actual font settings. This verifies native action dispatch, bounds, scalar persistence, refresh behavior and independent menu closure. It does not verify physical mouse movement/click hit regions, screenshot pixels, text clipping for every menu string, mixed monitor DPI, or performance. Rendered text option assertions do not prove screenshot appearance. The sibling frontend smoke includes twelve native typography probes, including a width-constrained full date, and isolated event-state transitions; the separate Lua settings suite covers additional control validation and save failures. Exclude generated `.runtime` directories from distribution.
