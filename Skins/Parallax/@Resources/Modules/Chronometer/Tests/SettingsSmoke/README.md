# Native Chronometer settings smoke

Run from the repository root using the existing Rainmeter installation:

```powershell
& '.\Skins\Parallax\@Resources\Modules\Chronometer\Tests\SettingsSmoke\Run-Smoke.ps1' -ColumnWidths 180 -Columns 1 -Scales 0.75
```

Optional `-TitleFontSize 12 -HeaderFontSize 10 -FontSize 10` and `-BorderThickness 4 -DividerThickness 4` override only the copied global settings. The lifecycle fixture starts with all four sections shown. It toggles every section off and back on through the production settings meters, verifies saved flags and Shown/Hidden readouts, and asks the refreshed countdown's test measure to verify actual compact height and visible/hidden dimensions. An existing event's exact saved bytes and the unchanged running timer's deadline must survive every toggle. The default timeout is 30 seconds to accommodate this longer lifecycle.

Latest verification, 2026-09-11, after adding section visibility controls: **two focused cases passed, 1,610 checks, no Rainmeter error entries** on Rainmeter 4.5.26.3894. Both start at width 180 and Columns 1, then change the running countdown to Columns 2. The default typography case uses Scale 0.75; the other uses Scale 2, title/header/body sizes 12/10/10 and border/divider thickness 4. Each passed 805 checks, including all eight section toggles and saved-state preservation. These lifecycle runs preceded the final four-pixel timer-row height correction; the settings menu and lifecycle behavior were unchanged. The previous event-controls check passed 408 checks and the original menu passed 388. The runner also accepts Columns 1/2, widths 180/200/240/280/320 and scales 0.75/1/1.25/1.5/2; this is focused evidence rather than a full combination matrix.

The test stages the production countdown and settings subconfig, backend scripts, shared resources and existing bundled fonts in its own unique `SettingsSmoke/.runtime/run-<guid>/` directory. Only copied settings are changed: the clock starts in 24-hour format, and the first two timers have known 1500/300-second durations. A test Script measure is appended to each copied skin. The copied settings menu's initial `Update=-1` is replaced in place with `Update=1000` for test orchestration; the production menu remains driven by clicks.

Native checks dispatch the production gear action to open the menu and inspect every actual menu meter's rectangle, panel dimensions, gutters and populated readouts. With two timers running, the test dispatches the menu's actual clock, duration-plus and width actions. It verifies the literal `%I:%M:%S %p` format survives `!WriteKeyValue`, the clock renders it after refresh, the duration increases by the selected 60-second step and resets only that timer, and the other timer keeps its exact saved deadline through every refresh. The width setting changes the countdown while the open settings menu remains two pitches wide. Finally, the actual close action deactivates only the menu; the countdown remains loaded and continues advancing. Saved isolated Rainmeter.ini active states are checked after exit.

The event adapter is staged with the other production Lua files. This lifecycle fixture creates an isolated future event named `Visibility event` using production `EventCore.encode`, records its exact bytes and explicitly reloads it. Its bytes remain unchanged through every section toggle and settings refresh; the final countdown still shows the saved name. The earlier 408-check run instead covered an initially unset event and verified that unrelated settings controls created no event file. The event configuration button is checked for native bounds with the other menu meters, but its action is never dispatched. This harness does not open the event editor or exercise its GUI Save/Cancel behavior.

The event assertion now expects the label `Countdown to Visibility event:` and a separate compact value such as `5d 3h 20m 10s`. This assertion update was not rerun as a separate lifecycle case for the compact display change; the focused frontend smoke verifies the new adapter text and layout.

A baseline file outside the refreshed countdown skin prevents test state from resetting when a production setting refreshes the module. The native snapshot store supplies the deadline assertions. The test sends no unqualified CLI bangs and never changes the live Rainmeter configuration. Each instance is launched with an existing, absolute isolated SkinPath and its own INI file. Only the returned process can be stopped on timeout. Generated directory paths are verified before recursive cleanup. Both skins use zero opacity; no downloads or dependency installation occur.

Four native text probes cover the menu title, visibility button, seven-day duration and saved-status text using their actual font settings. This verifies native action dispatch, bounds, scalar persistence, refresh behavior and independent menu closure. It does not verify physical mouse movement/click hit regions, screenshot pixels, text clipping for every menu string, mixed monitor DPI, or performance. Rendered text option assertions do not prove screenshot appearance. The sibling frontend smoke includes twelve native typography probes, including a width-constrained full date, and isolated event-state transitions; the separate Lua settings suite covers additional control validation and save failures. Exclude generated `.runtime` directories from distribution.
