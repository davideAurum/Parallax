# Native Chronometer frontend smoke

Run `./Run-Smoke.ps1` from this directory in PowerShell with an existing Rainmeter installation. The default matrix covers painted widths 180/200, Columns 1/2 and suite scales 0.75/1/1.25/1.5/2: 20 cases. `-Fixtures Default,Edge` runs both fixture sets: 40 cases. No dependencies are installed.

Reusable invocation from the repository root:

```powershell
& '.\Skins\Parallax\@Resources\Modules\Chronometer\Tests\Smoke\Run-Smoke.ps1' -Fixtures Default,Edge
```

Optional `-ColumnWidths 180`, `-Columns 1`, `-Scales 0.75` and `-Fixtures Edge` select individual cases. Widths 240/280/320 are also accepted for additional testing; the native results below cover 180/200 only.

For the section-visibility matrix, use `-VisibilityMasks (0..15) -LayoutOnly -ColumnWidths 180 -Columns 1 -Scales 1`. Mask bits are Clock=1, Uptime=2, Event=4 and Timers=8; 0 hides every section and 15 shows every section. The default mask is 15. `-LayoutOnly` uses a four-tick native run for hidden dimensions, compact height, section adjacency, visible text fit and header-gear behavior. It does not repeat the event/timer behavior sequence for every mask.

Typography can be overridden in the copied fixture with `-TitleFontSize 12 -HeaderFontSize 10 -FontSize 10`. Optional `-BorderThickness 0`/`4` and `-DividerThickness 0`/`4` exercise the shared surface settings. Omitted overrides inherit the staged user settings. Derived layout variables are evaluated with Rainmeter's formula parser, and only visible section meters participate in text-fit and non-overlap checks. Hidden sections must have zero native meter dimensions, while their unused text probes remain empty.

The runner stages copies of the production entrypoint, timer/event adapters and engines, snapshot store, module defaults/layout/styles, shared styles/defaults/geometry, bundled font files and user settings in a unique generated `Smoke/.runtime/run-<guid>/` directory. It changes only copied settings, pins the fixture's clock to `%H:%M:%S`, and appends a test Script measure, one isolated uptime formatter and twelve transparent text probes. The separate clock probe still covers twelve-hour text fit. Each case launches a separate Rainmeter process with its sole argument set to that case's absolute INI path. The copied skin retains its normal one-second update interval and production controls.

Checks discover every production meter and cover existence, valid dimensions, exact window/panel sizes, transparent gutter geometry and containment inside the painted border. Pairwise assertions check label/status, countdown/control and list-selector separation, vertical row separation, and header/footer ordering. Each section-top divider belongs to the section below it: `MeterUptimeRule`, `MeterEventRule` and `MeterTimersRule` must share their owner's visibility and sit at its exact native top coordinate. Hidden dividers must have zero dimensions and their Y must collapse to Inset. The former clock-bottom rule is absent, and no visible boundary line may remain after the final visible section; header-only and clock-only cases have no section dividers. Zero-height horizontal Shape lines are allowed; String meters still require positive dimensions. The hidden gear is checked separately: it starts with zero native dimensions, the production `MouseOverAction` reveals it inside the panel, and the production `MouseLeaveAction` hides it again. These are configured action dispatch checks; the test does not move a physical pointer. These checks use aligned meter rectangles: in the installed [MeterString implementation](https://github.com/rainmeter/rainmeter/blob/v4.5.26.3894/Library/MeterString.cpp), `GetX()` and `GetY()` apply StringAlign, while the `true` argument returns the anchor coordinates.

Twelve native String probes inherit their target meters' font, weight, style and padding. The title/header/body role samples are `Chronometer`, `1 / 3 Focus`, `Deep work` and `All lists: 10 running / 2 done`. Value/control samples are `11:59:59 PM`, `9999d 23:59:59`, `7d 00:00:00`, `Resume` and `Fix duration`. Separate event probes use `Countdown to A:` and `99999d 23h 59m 59s`; each must fit its own line's width and height. The event value probe covers five day digits as a width sample, not a selectable 99999-day deadline. Long event names clip independently in their fixed label box and remain complete in the tooltip. The full-date sample, `Wednesday, 30 September 2026`, uses its actual width with `ClipString=2` and no fixed height, so its naturally wrapped height must fit the production meter. Probe text is transparent instead of using `Hidden=1`, because hidden meters' [native GetW/GetH methods](https://github.com/rainmeter/rainmeter/blob/v4.5.26.3894/Library/Meter.h) return zero. Probes for hidden sections remain empty. Already-bundled IBM Plex Sans files are copied to the isolated resources; this runner never downloads or installs fonts.

The production uptime must use the built-in measure with no forced `SecondsValue`. Its nonnegative numeric seconds must agree with its displayed day/hour/minute/second fields and advance over the existing update sequence. A separate test measure copies the production format and uses the documented [SecondsValue override](https://github.com/rainmeter/rainmeter-docs/blob/master/source/manual/measures/uptime.html) to verify zero, minute/hour/day boundaries and the 9999-day text-fit sample. These forced samples never replace the production system measurement. The row's label/value separation and ordering between both dividers and the countdown list are checked using actual native rectangles.

Event checks run sequentially during the same nine-tick test instance. The harness starts with no event file, writes valid fixtures using production `EventCore.encode` into the isolated settings path and invokes only `MeasureEventCountdown.Reload()`. It verifies the `Countdown to <name>:` label and compact `5d 3h 20m 10s`-style units on the immediately following row, future advancement, agreement with the saved deadline, the local target in the tooltip, reserved-character sanitization and unchanged persisted bytes during updates. An expired event shows `Event reached: <name>` with `0d 0h 0m 0s`; corrupt bytes stay unread until explicit Reload and then show `Event unavailable` with settings repair guidance. A future local-midnight fixture checks the tooltip date, and a cleared record returns `No event set` / `Add in settings`. Both event lines start at the left content edge with exact vertical adjacency. There is no separate event heading, inline edit link or target-date row. No editor RunCommand action is dispatched, so GUI entry, Save/Cancel and timezone/DST selection are outside this harness's evidence.

The test also verifies native clock/date output, production `!CommandMeasure` start/pause/list selection/reset, resulting text options after actual meter updates, paused-state retention, and readable snapshot files. The Edge fixture changes only copied configuration: a long list name, a long first-timer label, a 604800-second first timer, and an invalid second duration. It verifies long names stay in fixed clipping boxes, the seven-day value remains complete, and invalid timers show `Fix duration` with `--:--:--`, persist as disabled, and cannot be started.

The test skin uses zero opacity to avoid changing desktop presentation. It quits its own Rainmeter instance through `SKIN:Bang('!Quit')`. Update checks are disabled. An existing test SkinPath is verified before launch; no CLI bangs are sent to Rainmeter. Timeout termination targets only the process returned by the runner. Cleanup validates the exact generated path before removing it. The final focused runs exited normally and their generated run directories were removed, as did the historical 40-case matrix. Exclude the whole generated `.runtime` directory from distribution.

Isolation follows the installed version's [official Rainmeter initialization source](https://github.com/rainmeter/rainmeter/blob/v4.5.26.3894/Library/Rainmeter.cpp): distinct INI paths have distinct instance mutexes, while unqualified command-line bangs may reach another instance.

These checks establish native loading, layout geometry, text metrics, control dispatch, updated text options, and snapshot integration. They do not inspect screenshot pixels, prove the font family actually selected by the renderer, check mouse hit targets, exercise mixed Windows monitor DPI, perform actual process-restart/global-refresh scenarios, or measure CPU/power cost. Root owns the separate all-suite visual capture. The separate logic suite tests restoration and retry semantics with controlled inputs. This is prototype validation, not release or performance certification.
