PARALLAX GPU - SENSOR MAPPING

GPU OVERVIEW

The inset beneath the header identifies Windows' preferred high-performance
discrete graphics adapter. A one-time query at skin load/refresh reads the
Windows DXCore hardware and integrated flags, excluding integrated and
software graphics. It does not guess from a vendor name or memory size.
Hover the name for its full text. An external GPU may be preferred over an
internal discrete GPU; this is not necessarily the display-driving adapter.

The original AdapterInfo.cs.txt source is compiled by Windows PowerShell
once per refresh. No plugin download or dependency installation is needed.
This metadata requires DXCore and a compatible D3D12 graphics driver.
Unsupported/query-failure states display GPU name unavailable. No match
displays No discrete GPU found; multiple discrete adapters without supported
performance ordering display Multiple discrete GPUs. Refresh to retry after
hardware or driver changes. No integrated adapter is used as a fallback.

The detail beneath the name shows that same GPU's total dedicated video
memory and type, detected automatically. When the installed NVIDIA driver offers
NVAPI, a read-only query matches its adapter to the selected DXCore LUID and
reads physical memory capacity and type. No vendor API is downloaded.
Otherwise, the line uses DXCore's dedicated video memory capacity and shows
the memory type as Unknown. This is not current usage or shared system RAM.
An unavailable capacity displays Unknown; the skin never guesses a memory
type from the GPU name. Hover the line for its full text and source details.

Immediately after the memory type, @ introduces the base graphics clock in
MHz, followed by the boost clock in parentheses. The installed driver must
supply these for that same matched adapter. They are reference clocks, not
the current operating clock. A missing base or boost value displays --;
the tooltip explains each unavailable field. This combined detail wraps
within a fixed two-line area at narrow widths; hover for the complete text.
The Clock reading below is the current graphics clock by default; an explicit
HWiNFO override can supply a separately selected clock measurement.
The name and combined details refresh together, without polling or saved device
specifications.

GPU MEMORY AND DRIVER ACTIVITY

VRAM shows occupied / physical total memory and an occupancy bar. Occupied
means physical memory minus currently available framebuffer, including memory
outside the allocatable framebuffer. Hover for the free and allocatable amounts.
These readings use the installed NVIDIA driver for the detected discrete card.
Shared RAM separately shows Windows-reported GPU residency in system RAM;
its tooltip includes committed bytes. It is not a maximum memory allowance,
and committed and resident are different accounting values that need not match.
Memory amounts use binary MiB/GiB units; the overview retains its existing format.

GPU, Memory ctrl., Video and Bus are separate driver activity percentages.
They describe busy time, not memory allocated to these functions. Do not add
the percentages together. GPU is the NVIDIA activity domain, not specifically
a Windows D3D engine. Video is a combined driver domain, not separate encode
and decode readings. Bus is activity, not a transfer rate in bytes per second.
Valid idle domains display 0%; unsupported or unavailable domains display --.

These readings share the existing direct temperature helper and sampling
cadence. They need no HWiNFO mapping, additional host or additional session
file. Each feature can fail independently; Windows shared RAM can remain
available without the NVIDIA interface. Other-vendor dedicated-memory usage
and activity providers are not implemented. Identity changes and stale samples
clear all direct readings. Refresh GPU to detect new hardware or retry.

PROCESS ACTIVITY SCOPE

The five process bars show ranked process-engine activity across exposed
GPU adapters. Each row has a percentage and a bar scaled from 0 to 100%.
The process identity and engine identify each observation; hover a row for
the full details. Different engine contributions are not added together.
One process can occupy several rows for different engines or adapters.
An empty or unavailable observation leaves its bar empty and its value --.

The activity percentage is one process's reported contribution to one GPU
engine, selected as the highest exposed instance across all adapters. The
PID and engine type identify that observation. It is not an adapter total
or Task Manager's GPU total. Hover the value for the complete counter name.

-- / Idle / unavailable means there is no ranked nonzero observation.
Startup, no activity and an unsupported / missing counter look the same.
The counter has no freshness timestamp; a collection error can retain an
older observation. Unsupported counter format means scope could not be
verified. On Rainmeter 4.5, another skin's GPU counter can affect name
translation; unload conflicting GPU skins and refresh to troubleshoot.

DIRECT GPU TEMPERATURE

Temperature reads the detected discrete GPU directly through the installed
NVIDIA driver. It needs no HWiNFO export or sensor mapping. GPU Settings shows
Driver; Refresh restarts detection. AMD/Intel direct temperature providers are
not implemented. Unsupported or failed readings remain explicitly unavailable.

GPU Temperature is the regular graphics-chip reading. Hotspot is the hottest
measured area within that chip, distinct from VRAM temperature. This public
NVIDIA interface does not provide a separate hotspot reading on the tested GPU.

One persistent hidden helper polls at the sensor/skin interval (at least 1 second,
at most 30 seconds). It launches no command per sample. The helper matches the
exact adapter identity, and stale or mismatched samples are rejected. Refresh
GPU after changing cards or drivers. Session files are bounded, randomly named
and stored only in Windows temp; closing GPU stops the helper and removes them.

DIRECT GPU POWER AND CLOCK

Power and Clock default to Driver in GPU Settings. Power reads milliwatts from
the installed NVIDIA Management Library (NVML) and displays watts. It covers
the GPU and associated circuitry, including memory; it is not a percentage of
TDP. NVIDIA reports instantaneous power on older architectures and GA100,
and a one-second average on Ampere except GA100 and newer architectures.
A successfully returned zero-power reading is valid.

Clock uses the installed NVIDIA driver's current graphics-clock domain,
converting kHz to MHz. It is separate from the base/boost specifications in
the overview and does not substitute memory or video clocks. Zero or a missing
clock is unavailable. Power and clock failures do not suppress other readings.

Direct power requires the 64-bit telemetry host; a 32-bit host reports power
Unsupported while its other supported readings can continue. NVML is used
only when already installed in Windows System32 or
Program Files\NVIDIA Corporation\NVSMI. The existing hidden telemetry host
loads it directly; there is no nvidia-smi polling, binary download or extra
process. Complete NVAPI-physical and NVML inventories must uniquely match the
exact selected DXCore/NVAPI adapter's PCI identity. The helper retains the PCI
domain, rejects nonzero PCI functions and checks identity around each power read.
Unsupported drivers or ambiguous/missing identities remain unavailable.

Both readings share the existing sampling loop and three temporary session
files. Each source stays as selected: Driver never silently falls back to
HWiNFO, and HWiNFO never silently falls back to Driver.

OPTIONAL HWiNFO POWER / CLOCK OVERRIDES

Power and Clock can use explicitly selected HWiNFO Gadget exports instead.
Power source and Clock source select each reading independently. The HWiNFO
overrides toggle and Manual hive/key controls apply only to selected overrides.
This skin installs nothing and needs no external HWiNFO plugin or Shared Memory.

1. If you choose to use HWiNFO, follow its license for your use. In HWiNFO's
   sensor settings, enable reporting to Gadget and select Report value in
   Gadget only for the GPU power and clock sensors you want.
   Read each sensor's explanation so you know whether power is board or
   chip power, and clock is core or memory.

2. Hover over GPU and click the gear to open the separate GPU Settings
   utility. It can stay open beside the GPU meter. The official Rainmeter
   guide covers HWiNFO Gadget setup:
   https://docs.rainmeter.net/tips/hwinfo/

3. Choose the registry hive holding your exports (Current user or Local
   machine). Click Power override or Clock override to read the exported list.
   Use Previous/Next to browse, and hover a candidate for its complete
   identity and value. Select the correct GPU and measurement yourself;
   the list does not guess which reading you intended. Clear removes only
   that row's mapping. Rescan reads the list again after HWiNFO changes.

4. Set Power source or Clock source to HWiNFO for each override you want to
   use, and switch HWiNFO overrides On. Selecting or clearing a mapping does
   not change the source or enable overrides. Each control saves immediately
   to GPU.inc and refreshes only the GPU meter. X closes only settings.

Advanced opens GPU.inc for custom registry paths or manual mappings.
The default key is SOFTWARE\HWiNFO64\VSB. A manual mapping consists of
the actual index N plus exact SensorN and LabelN strings in the matching
GPU<Power/Clock>Index/Sensor/Label options. Do not guess indices
or copy another computer's mappings. Save advanced edits, reopen settings,
then Refresh GPU. Sensor names with active Rainmeter syntax are not accepted
by the picker; ordinary HWiNFO ordinal markers such as [#0] are supported.

Values retain the unit provided in ValueN. Hover a value to see its full
sensor and element identity. There is no assumed Celsius, watt or MHz
conversion. A raw numeric zero is valid when the identity, registry
membership and formatted value are present.

For a selected HWiNFO source, Off means optional reads are disabled.
Unmapped means the index or identity is absent.
Unavailable: required exports or valid values are absent. Check mapping:
the index is invalid or the exported sensor / label no longer matches.

Adding or removing Gadget exports can change indices. Recheck mappings
after any such change. Exact identity checks help detect index drift but
cannot distinguish two sensors with identical names and labels.

Snapshot / age unknown is deliberate. These registry exports have no
sample timestamp; HWiNFO may leave values behind after it stops. A repeated
value does not prove a stall, and a running process would not prove fresh
sensor data. Do not use these snapshots as temperature or power alarms.

Registry measures start disabled; only explicitly selected HWiNFO overrides
with the toggle On enable their bank. A shared export-name check runs if either
bank is needed. Enabled reads follow SensorInterval (normally 2000 ms), rounded
up to a whole number of skin updates. HWiNFO controls its own collection cadence.
The UsageMonitor GPU category polls independently at 1 Hz. To release this
skin's GPU category consumer, unload GPU; changing MetricsInterval does
not throttle that worker. Another loaded consumer can keep it running.

LAYOUT AND PERSISTENCE

GPU.inc is a persistent [Variables] file. Columns=1 or 2 selects its width;
default PanelHeight=560 fits the GPU overview, memory/activity, process bars and sensor rows.
GPU Settings offers Meter width and Fit panel height controls. To resize an
older preserved height for this compact layout, click Fit panel height to
use 560 logical pixels. Larger saved heights stay effective, and smaller saved
heights render at the 560-pixel minimum without changing the saved value.
The settings window uses its own two-column, 648-logical-pixel layout,
independently of GPU. It follows Global Settings with aligned labels and
shaded value fields, spaced 28 logical pixels apart. Display contains width
and fitted height. Provider setup contains the Driver temperature source,
independent Power/Clock source selectors, and explicit HWiNFO override controls;
exported choices appear below. GPUPowerSource=0 and GPUClockSource=0 select
Driver; value 1 selects HWiNFO and also requires GPUEnableSensors=1. Old mappings
and enablement choices stay saved when switching sources. Setup/recovery controls
stay available when a provider is disabled or unavailable.
Section lines follow the global divider color and thickness. Temperature
Refresh restarts detection without saving choices. Legacy temperature
mapping keys remain preserved but are not used by the direct driver source.
The gear replaces the header activity value only while hovered; activity
continues updating. Global settings opens the shared appearance controls.
Export discovery runs only when choosing a sensor row or pressing Rescan.
No history or user sensor listing is saved. Direct temperature, memory, activity,
power and clock share the bounded temporary session described above.
