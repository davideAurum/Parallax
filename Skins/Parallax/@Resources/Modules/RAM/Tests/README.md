# Isolated RAM native smoke check

Run from the repository root after shared styles and RAM edits are stable:

```powershell
& 'Skins/Parallax/@Resources/Modules/RAM/Tests/Test-RAMNative.ps1' -TimeoutSeconds 60
```

The script uses an existing Rainmeter executable. `-RainmeterPath` may select a different existing installation. `-PrepareOnly` creates the snapshots without launching anything.

For the focused grouped-overview, PAGE and process-table check, use the existing script with `-FixtureOnly` (optionally also `-PrepareOnly`). This prepares six cases across widths 180/220, scales 0.75/1/2 and both column modes. Every copied inventory, PAGE helper, numeric-input helper and process provider becomes a Calc measure before launch; the focused mode refuses any remaining RunCommand or UsageMonitor provider in either RAM or its Settings utility and records zero inventory queries, paging-file/input helpers and process-provider cases. Fixtures cover duplicate modules, mixed groups, a long manufacturer name, five ranked processes and unavailable process data. The six cases retain the existing control/persistence checks and compare the summary's actual wrapped height with the overview height and all following row, graph and process-table positions. This mode never runs an inventory query, paging-file helper or process-category worker.

Twenty RAM copies cover widths 180/200, Columns 1/2, and Scale 0.75/1/1.25/1.5/2. One isolated instance loads those copies offscreen with zero alpha, using its own absolute INI and existing SkinPath. Sources are read once, and only RAM, its Settings utility, required shared includes, and already bundled fonts are copied. Each case has isolated settings/apply groups and an initially inactive Settings config. Unit modes alternate between decimal GB and MB; two-decimal values, long titles, border widths 0/1/4 and divider choices 0/4 are exercised. Ten cases use default fonts and ten use maximum title/header/body sizes 12/10/10 with distinct semantic colors. Actual native memory measures keep their normal cadence and values.

Displayed GB divides bytes by 1,000,000,000; MB divides by 1,000,000. The existing `RAMUseMiB` saved selector and meter IDs ending in `GiB`/`MiB` remain unchanged for compatibility. Assertions distinguish those identifiers from the visible GB/MB labels and decimal divisors, including the Settings utility's load, toggle and reopen labels.

The compact `RAM:` and `PAGE:` rows display used/total pairs in the selected units. RAM retains native PhysicalMemory used and total measures. PAGE now displays paging-file-only space in use and current allocated capacity, excluding physical RAM and system commit accounting. Its legacy meter IDs remain, but native SwapMemory bindings and meter scaling are absent. `PageFileFixture.lua` parses one fixed `RAM_PAGE` wire with the production model and formats cached bytes; the same six native copies cover normal bytes, zero usage, no paging file, unavailable, unsupported and stale data. Every display-harness mode uses PAGE fixtures and removes the helper start action. The actual resident provider has its own separate validation script.

`PageFileModelTests.lua` checks byte/count bounds, canonical numeric fields, decimal formatting, all statuses, freshness, sequence/epoch ordering and exact temporary-session paths. The existing native harness also loads the production `PageFile.lua` controller into a mocked Lua environment. Provider bangs and session reads/writes remain in memory. These checks cover one bootstrap/host launch, cached reformatting with no IO or launch, stale fallback and recovery, zero usage, rejected payload changes under the same sequence, no-file status and session-only cleanup. The provider mock distinguishes documented RunCommand initial status -1 from an unlaunched native cache that can still read 0; running is 0, completion is 1, and terminal failure is 103. Neither unlaunched status establishes helper ownership. Focused lifecycle cases check cold stop, tracked bootstrap/host stop, cached-zero completion refresh, bootstrap timeout, lease failure and idempotent cleanup. All controller meter updates must target PAGE; the only non-provider measure update is its event-only ratio Calc, preserving physical RAM/history. The native copies verify PAGE text/tooltips and a single fixture parse throughout settings changes. These checks do not establish actual paging-file measurements on the test computer.

The same six native fixtures vary shared `DataBarThickness` through 1, 6, 6.25 and 12 logical pixels. RAM and PAGE each have a bar below their own readout. Tests check separate physical-RAM and paging-file ratios, shared pixel rounding, a positive visible height at the 1 px / 0.75 scale endpoint, and clearance before following content. PAGE has a visible empty bar for known zero usage, and no bar for missing, stale, no-file or zero-allocation readings. Independent `RAMShowBar` and `RAMShowPageBar` changes preserve the other bar and cached values. Each bar reserves additional space above 6 logical px, giving minimum height `242 + RAMInfoHeight + GraphHeight + 2*Max(0,DataBarThickness-6)`. Source checks retain the existing matrix with targeted thickness cases at widths 180/220 and scales 0.75/1/2. Thin bars preserve their logical centers with pixel quantization; assertions allow one pixel of native rounding and use effective options for hidden geometry.

RAM Settings uses the Global Settings pattern: labels on the panel surface and compact shaded, padded value fields at 28 px pitch. Its two-column, 340 px panel contains six controls, including separate RAM bar and PAGE bar toggles. Shared utility styles supply typography and field appearance; local modifiers only set column geometry and UI groups. Semantic section separators use `StyleRule` with `DividerColor`/`DividerThickness`; the existing native cases cover enabled and zero-width dividers. Source geometry includes String padding in outer bounds. Memory units and the two precision values use shared 18/56/18 px previous/value/next steppers with 2 px gaps and 20 px frames. Units wrap; numeric arrows clamp to the supported integer range 0–2. The center, frame and label invoke the same cycle or typed-input action. Bar and history toggles retain shaded padded fields. Source and native checks verify shared styles, centered unpadded stepper text, frame/arrow gaps and bounds, toggle padding, label alignment, matching actions, absence of full-row backdrops, global navigation and independent close behavior. Existing narrow-width and maximum-font cases cover the updated layout without expanding the native matrix.

Settings section headings use `AccentColor` with `HeaderFontSize`; ordinary monitor headings keep `HeaderTextColor`. RAM has no visibility-dependent settings details to collapse. The two bar options and history are their own always-accessible toggles, while memory units/decimals still apply to RAM, PAGE, inventory and processes, and percentage precision applies to the header. Existing native off/on phases verify that all six labels/fields and every formatting stepper frame/arrow stay visible, usable and inside the fixed settings window, with their saved values intact and independent formatting preferences unchanged.

In the full twenty-case mode, the first copy runs the real refresh-only hardware query and the UsageMonitor process counters. The other copies use Calc process fixtures; eighteen also use explicitly test-only `RAMINFO2` inventory fixtures covering known, mixed, partial, unknown and unavailable metadata. Their provider is replaced with a Calc measure in the copied source, so that mode launches only one PowerShell query. The final copy leaves its inventory provider unfinished to check the view's timeout fallback. `InfoModelTests.lua` additionally checks protocol validation, decimal byte formatting, transfer rates, memory types, safe manufacturer text and grouping inside Rainmeter's Lua runtime. `ProcessModelTests.lua` checks ranked/missing entries, literal process names, decimal formatting and private-working-set explanations. Native fixture assertions verify the exact `Process` heading, row text, rank order, availability, unit changes and placement above the bottom history graph. No fixture replaces live PhysicalMemory readings.

The test checks native skin/meter bounds, transparent gutters, PhysicalMemory ranges, unit/percent/history bindings, grouped hardware summary text, automatic overview height and log errors. Double-column copies, and every focused copy, preserve `PanelHeight=170` and verify that the content fits through the computed minimum height. The actual gear action opens each dedicated Settings config; `SettingsNative.lua` exercises all six controls across configs, verifies saved keys and immediate summary-capacity formatting, checks utility-only geometry and the absence of telemetry measures, and closes/reopens the utility twice to verify persistence. The main meter checks hover/leave and uninterrupted history counting while text wrapping moves the existing graph. Transparent unconstrained String probes measure actual native font heights after rendering, including the visible GB/MB value, and compare them with allocated boxes. The test never sends command-line bangs and stops only its own process. It does not read or change live user configuration, install fonts/plugins, or capture the desktop.

Evidence remains under a unique `Tests/.runtime/ram-native-*` directory. This entire Tests subtree is excluded by the existing staging policy. Do not distribute its instrumented skins or runtime logs. Failed runs are retained for inspection; the test performs no recursive deletion.

Bounds, clipping options and natural font heights do not prove complete visual readability or horizontal text fit. Action execution does not prove physical pointer-event delivery. The real query may correctly settle to Unavailable where Windows denies inventory access; its state is recorded separately in `summary.json`. Settings reopen persistence is tested; full RAM unload/reload persistence, firmware accuracy, full-history rendering, performance, mixed Windows DPI and release readiness remain outside this smoke check. The coordinator performs actual window capture and visual inspection separately. A longer harness deadline accommodates many utility activations under concurrent test load and is not a performance result.

Rainmeter Lua APIs follow the [official Lua scripting documentation](https://github.com/rainmeter/rainmeter-docs/blob/master/source/manual/lua-scripting/index.html).

The native numeric controls execute the real decrement-arrow action twice from the fixture value 2 to 0, preserving the existing unit/precision assertions. Typed center actions are checked without launching a popup. The production settings controller runs separately in an in-memory mock covering bounded adjustments, wrapped units, validated typed results, cancellation, invalid input, pending/repeated completion and input cleanup. Numeric input uses the shared one-shot SettingsInput helper in production; this display harness replaces it with an inert Calc and does not validate actual HWND positioning or keyboard delivery.
