# ModernGadgets-inspired appearance, revision 2

User direction, 2026-09-11: make every utility look substantially closer to raiguard's **ModernGadgets** as the starting point. This supersedes the earlier spacious dark-card interpretation. Keep Parallax's customization, independent modules, source semantics and snapping geometry.

Visual reference: [official preview](https://raw.githubusercontent.com/raiguard/ModernGadgets/master/Wiki/preview.png). The local research copy is `build/reference/moderngadgets-preview.png`, outside distributable sources. Behavior/style reference: [ModernGadgets stylesheet](https://github.com/raiguard/ModernGadgets/blob/master/Skins/ModernGadgets/%40Resources/StyleSheet.inc). Implement original Rainmeter meters; do not copy upstream code or images. Its exact default panel width is 150 logical pixels; Parallax starts at 220 to accommodate its expanded controls.

## Shared defaults

- Painted column 220 px; double 448 px with the existing 8 px gutter. This adopts the CPU meter's current width as the shared standard. Validation widths are 180, 200, 220, 240, 280 and 320; suite scale 0.75, 1, 1.25, 1.5 and 2. PanelPadding=6, CornerRadius=3.
- Neutral near-black background `15,15,15,255`, graph/inset `25,25,25,255`, border/divider/track `50,50,50,255`, primary text `220,220,220`, secondary text `175,175,175`, Accent 1 `137,190,250` and Accent 2 `181,161,226`.
- Panel titles use `TitleFontSize=10` / `TitleTextColor=220,220,220`, weight 600. Ordinary monitor section headings and table labels use `HeaderFontSize=8` / `HeaderTextColor=175,175,175`, weight 600. Settings section headings use header font size and Accent 1 (`AccentColor`); table column labels retain their header role. Ordinary body text uses `FontSize=9` / `TextColor=220,220,220`, weight 500. Global Settings supports title 6–12 pt and header/body 6–10 pt, including two decimal places. FontFace=IBM Plex Sans, bundled with the user's explicit approval under SIL OFL 1.1 in `@Resources/Fonts` and `@Resources/Licenses`. Follow `FontFace` rather than hardcoding a font. The fonts load privately in Rainmeter; module tasks must not download fonts or assets.
- The Default theme has an opaque background, 1 px border and section dividers, and 3 px corners. `BackgroundColor` carries background alpha; the transparency field derives and updates that alpha. `BorderThickness` and `DividerThickness` accept 0–4 logical px, with 0 hiding the stroke. The border is inset by half its scaled thickness to stay inside the panel. Shared transparent gutters still define snapping. Avoid shadows/large empty margins.
- One compact header: title-row identity icons and titles share the center at 15 logical px below the panel origin, within a 22 px title row. Icons are original or explicitly attributed as recorded in each module. Scale icon paths and strokes with `TitleIconScale=Scale*TitleFontSize/10`; a nominal 14 px icon grows to 16.8 px at the current 12 pt title size. Title text uses `StyleTitle|StyleTitleRow`, with `CenterCenter` for intentionally centered titles. Reserve icon width plus a 4 px scaled gap before left-aligned titles, and center right-side controls/readouts on the same row. Media's Monitor Play title icon follows the shared title-size and center contract; its separate Audio Lines body-source icon stays 14 logical px, scaled by the suite independently of title font size. Offset surfaces translate the whole row together. Label/value rows should share baselines, typically 16–18 logical px apart.
- Scalar data bars use the shared 6 logical px default, adjustable from 1–12 px. Track and fill inherit `DataBarThicknessPx`, rounded to whole screen pixels with a one-pixel minimum. Keep colored activity on neutral tracks and reserve space for the supported thickness range.
- History graphs typically 42–52 logical px tall with a near-black inset, thin border and subtle horizontal grid lines. Use original data series colors; preserve unknown-history behavior and source semantics.
- Controls are small text/icon actions, not large padded tiles. Shared `StyleButton` padding is now 3,1,3,1 times Scale (adds 6 px width / 2 px height); H=18 times Scale. Tooltips supply full descriptions. Brief status text stays visible; lengthy provider caveats belong in hover text/docs.

Shared per-metric colors: CPUColor (red), RAMColor (cyan), GPUColor (green), DiskReadColor (green), DiskWriteColor (yellow), NetworkInColor (yellow), NetworkOutColor (green), MediaColor and ClockColor (blue). These are user-editable global variables. Individual modules may override them in their User include.

`AccentColor` remains the compatibility key for Accent 1 and primary controls. `AccentColor2` supplies secondary controls through the FontColor-only `StyleSecondaryButton` modifier. Append that modifier after `StyleButton`; do not let it replace local geometry. Section rules use `DividerColor`/`DividerThickness`; table-header underlines use independent `TableHeaderBorderColor`/`TableHeaderBorderThickness` (default `50,50,50,255`, 1 px); history grids retain `GridColor`. Use `StyleTableHeaderRule` where shared geometry fits, or the same keys with local geometry. Header thickness accepts 0–4 px; zero hides the lines. Scalar data bars use shared `DataBarThickness` (default 6 logical px, matching CPU bars; range 1–12 with up to two decimals). Use `DataBarThicknessPx` from shared geometry (rounded to whole screen pixels with a one-pixel minimum) for track and fill, preserve row centers where space allows, and accommodate larger heights in the surrounding layout. Graph traces, equalizer band geometry, icon strokes and divider lines retain their own dimensions. Preserve semantic metric/status colors and deliberate size differences for clocks or readings. Global Settings uses fixed neutral control text so changing body typography does not make its editor unusable. ColorPicker also keeps an opaque neutral editor surface; its preview still reflects the selected target.

Independent utility settings follow the Global Settings structure described in [UTILITY-SETTINGS.md](UTILITY-SETTINGS.md): a separate double-column window, title and top-right close, shared context/link lines, then aligned labels and compact shaded value fields on a 28 px row pitch. Group controls into meaningful sections such as Appearance, Performance or Setup without adding empty sections. Use `StyleUtilitySettingsSection`, `StyleUtilitySettingsLabel` and `StyleUtilitySettingsValue`; optional `StyleUtilitySettingsRow` backs only the value field. Semantic section separators use `StyleRule` and divider settings; `StyleTableHeaderRule` and table-header settings apply only to actual column-header underlines. Adapt height and field widths to each utility's content while preserving its options, provider behavior and saved monitor geometry. This is the target layout contract; module reports record conversion and validation status.

In each independent utility settings panel, current values and available choices follow body `FontSize` and `TextColor`, including toggles and clickable numeric values. Section headings use `HeaderFontSize` and Accent 1 through `StyleUtilitySettingsSection`; command/navigation buttons retain their action accents. Preserve swatches and semantic diagnostic/disabled colors. Global Settings also uses Accent 1 for section headings while keeping fields and table column labels neutral; ColorPicker retains its neutral editor typography.

When an existing display visibility option hides a feature, collapse that feature's settings details and their occupied space. Keep its heading and re-enable control accessible, remove hidden hit targets, and reflow later content and settings height. Showing the feature restores its details and saved values. Collapse only dependent rows in mixed sections; controls shared with another visible feature remain available. Provider disconnection or unavailable telemetry does not hide setup/recovery controls, and this behavior introduces no new visibility preference or poller. The full behavior and validation contract is in [UTILITY-SETTINGS.md](UTILITY-SETTINGS.md#behavior-and-validation).

Below each independent settings title, show two compact lines: "<Utility> settings are found here." and the clickable "Global Settings are found here." Use the shared `UtilitySettingsNote.inc`, body size minus 1 pt, with body color for the first line and Accent 1 for the link. Leave both lines clear of the close control and the settings form below.
