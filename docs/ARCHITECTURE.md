# Parallax shared contract v2

## Ownership and scope

Each utility maintains its current required, bundled and optional dependencies in the Dependencies section of its module document. Update that list with implementation changes and document unavailable-feature behavior. [DEPENDENCIES.md](DEPENDENCIES.md) indexes those lists and the shared platform requirements; Global Settings and ColorPicker have entries in their integration-owned documents. Planned integrations remain separate from current dependencies.

The original task owns global settings, shared appearance/geometry, integration and packaging coordination. Eight dedicated tasks own Chronometer, CPU, RAM, GPU, IO, Network, Media and Visualizer. Media owns optional Spotify queue; Visualizer is a separately loaded output-device spectrum companion whose capture and spectrum includes Media also hosts in its opt-in [spectrum drawer](modules/Media.md#spectrum-drawer). IO owns disk capacity/transfer rates. Network is independently loadable and owns NIC throughput, adapter selection and traffic history.

The separate Welcome config is an integration-owned utility and the config the `.rmskin` loads after installation. It lists the eight utilities and Global Settings as check boxes, toggling each one with `!ActivateConfig` / `!DeactivateConfig`, and offers Load all and Unload all. It holds no preference of its own: loaded state is read from Rainmeter's own settings file on explicit events only, and each row matches its config's recorded skin-file position, so `Media\Setup.ini` does not check the Media row. See [WELCOME.md](WELCOME.md); adding an alphabetically earlier `.ini` to a listed config folder changes that position and must be reflected in `Welcome.lua`.

The separate ColorPicker config is a global-settings utility owned by the integration task. Preview remains local until Apply writes only the selected key, refreshes Parallax and closes the picker. Background edits preserve its existing alpha; other targets save opaque RGB. Cancel writes nothing. Twelve numeric Global Settings fields use the reviewed one-shot SettingsInput helper and fixed data-only result protocol; neither settings utility adds recurring collection work.

Implement original assets and code. ModernGadgets is design inspiration, not an imported dependency. The user's revised visual direction is much closer to its dense black instruments; follow `docs/APPEARANCE.md` revision 2 for the current contract. All colors remain configurable.

## Files and settings

Every config joins `[Rainmeter] Group=Parallax` and supplies a context action opening `Parallax\Settings`, `Settings.ini` (except the hidden, click-through [input-idle coordinator](#input-idle-coordinator), which has no reachable menu). Include these files in this order from a `[Variables]` section using numbered `@Include` keys:

1. `#@#Defaults.inc` (shared defaults).
2. `#@#User\Settings.inc` (persisted global choices).
3. Optional `#@#User\<Module>.inc` (module-owned overrides/defaults).
4. `#@#Geometry.inc` (derived dimensions).
5. `#@#Styles.inc` (shared meter styles).

Set `Columns=1` or `Columns=2` and `PanelHeight=<logical pixels>` BEFORE Geometry.inc, either in module User variables or the entrypoint. Do not override a user's module choices later in the entrypoint. Entry-point flags that shared geometry reads must also be settled before the entrypoint's last `@Include`: Rainmeter's final variable pass resolves forward references with values from its last include pass, so a flag overridden after the last include leaks its old value into anything that refers ahead to it. The one sanctioned exception to the include order is Media.ini, which reads `Modules/Visualizer/Fallbacks.inc` and `User/Visualizer.inc` before Defaults.inc so its spectrum drawer follows Audio settings while Media's own `Columns` and `PanelHeight` still win. Includes contain their own section headers. Rainmeter merges layered `[Variables]` sections by key. Keep include identifiers unique in an entrypoint. Use `@Resources/Modules/<Module>/` for module scripts and includes.

Global changes persist through `!WriteKeyValue` into `@Resources/User/Settings.inc`, then refresh only `Parallax` configs: `!RefreshGroup Parallax` for appearance changes, with stepper-arrow bursts debounced to one refresh about 0.8 s after the last click, and only the consuming configs for a refresh-interval preset (see [SETTINGS.md](SETTINGS.md)). Module settings may override global colors, fonts and `Scale` locally in their own User file. All persistable settings live in `[Variables]` for Skin Packager variable preservation. Ship every supported user key with a default. New keys must retain useful defaults during upgrades. Runtime data (timer state, queue caches, OAuth tokens) is separate from distributable configuration, with its persistence and migration documented by the module owner. No OAuth material in skins.

Global Settings groups appearance controls under Appearance and refresh presets/cadence under Performance. The Refresh field now wraps Balanced/Economy through previous/next arrows and a forward-cycling center. Its current label is inferred from all four saved intervals; unmatched values show Custom and remain untouched until an explicit choice. From Custom, previous selects Economy and next/center selects Balanced. No profile key, helper, collection process or layout-height change is added. Utility panels follow the [shared settings layout](UTILITY-SETTINGS.md), using named sections appropriate to their features and preserving saved monitor geometry. Settings section headings use Accent 1, while their values use body text. When a saved visibility choice hides a utility feature, collapse its dependent settings details and reclaim their space, keeping a heading and accessible visibility control. Restore existing values when shown again. Provider failures and unloaded skins do not define this visibility state; setup and recovery remain accessible.

The global Theme dropdown currently contains only Default. Its 37-key bundle matches shipped defaults and includes the theme identifier, font family and all three text sizes/colors, both accents, panel/background/divider/table-header styling, data bar thickness, padding/corners, graph styling, status colors and utility metric colors. It refreshes Parallax once. The theme leaves suite scale, column width, snap gap, cadence and module-owned includes intact; module appearance overrides retain precedence. `Theme=default` records the last applied base theme and is preserved with other global variables. [SETTINGS.md](SETTINGS.md) lists the exact bundle and controls.

Numeric fields accept scale 75–200%, column width 180–320 px, gap 0–16 px, rounding 0–24 px, title size 6–12 pt, header/body size 6–10 pt, background transparency 0–100%, border/divider/table-header thickness 0–4 px, and data bar thickness 1–12 px. Width/gap/rounding require whole pixels; other fields allow up to two decimals and optional appropriate unit suffixes. The helper receives only known keys and canonical launch values. RunCommand returns a fixed ASCII numeric/cancel protocol, and a fixed FinishAction calls Lua to read the result as data and validate it again. The helper writes no files; accepted changes use the shared persistence path above.

`BackgroundTransparency` is an input operation, not a persisted variable. It preserves background RGB and writes the nearest 8-bit alpha into `BackgroundColor`; zero percent is opaque and 100% fully transparent. The displayed value is derived from the saved alpha and rounded to two decimals: 37.5% becomes alpha 159, then displays 37.65%. The Default theme restores `BackgroundColor=15,15,15,255`.

## Geometry

`ColumnWidth=220` is the painted width of one panel at scale 1. This adopts the CPU meter's former 200+20 px width as the shared standard; CPU now uses the same geometry without an additive width override. `Gutter=8` is the visible gap between edge-snapped panels, included as equal transparent outer margins. `Scale=1` initially. These are editable choices, not a Rainmeter hardcoded snap distance.

- `UnitWidth = Round(ColumnWidth * Scale)`.
- `Gap = 2 * Round(Gutter * Scale / 2)` (even physical pixels).
- `Inset = Gap / 2`.
- `Pitch = UnitWidth + Gap`.
- `WindowWidth = Columns * Pitch`.
- `PanelWidth = WindowWidth - Gap`.
- `WindowHeight = Round(PanelHeight * Scale) + Gap`.

A single panel paints 220 px inside a 228 px window. A double panel paints 448 px inside a 456 px window: `2 * 220 + 8 = 448`. Two adjacent single windows occupy precisely the same width as one double window. Draw the panel at `(Inset, Inset)` and size it `(PanelWidth, PanelHeightPx)`. Use an invisible bounds meter (StyleBounds) so transparent margins remain part of the skin window. Do not add meters outside the declared window bounds. `StylePanel` draws the surface. Content starts at `ContentX/ContentY`; usable width is `ContentWidth`.

Use logical vertical positions multiplied by `#Scale#`, measured relative to `#Inset#`. Text should clip/truncate long content without growing the window. Use fixed declared widths; do not allow cover art or labels to change snap geometry. Width variants may share an entrypoint with a persistent Columns setting.

Title/icon rows share a vertical center: `TitleRowCenterY=Inset+15*Scale` and `TitleRowHeight=22*Scale`. Layer `StyleTitleRow` after `StyleTitle` for `LeftCenter` anchoring; intentionally centered titles use `CenterCenter`. A title-only settings panel uses the same center without adding an icon. Existing title-row identity icons use `TitleIconScale=Scale*TitleFontSize/10`, a nominal `TitleIconSize=14*TitleIconScale`, and `TitleIconGap=4*Scale`. Scale actual paths, shapes and strokes, then center their canvas on the title row. Title X and available width must reserve the resulting icon size, gap and any right-side control/readout. Media's Monitor Play title icon follows this contract. Its Audio Lines player icon stays 14 logical px and scales only with the suite; it shares the title center in double-width mode and the stacked player-row center in compact mode. Offset surfaces translate the shared center by their surface offset. Fixed-size gear/close controls keep their click targets and align to the row center. Keep following content clear as title sizes change; do not rely on enlarging a Shape meter's W/H to scale its artwork.

Rainmeter `SnapEdges` is a per-skin setting in Rainmeter.ini, not an arbitrary spacing option. Leave normal Rainmeter snapping enabled; a user can disable it or hold Ctrl while dragging. Validate single/double alignment at 100%, 125%, 150% and 200% suite scale and mixed Windows DPI before release. See [official skin settings](https://github.com/rainmeter/rainmeter-docs/blob/master/source/manual/settings/skin-sections.html).

## Appearance

Shared typography uses `FontFace`, `TitleFontSize`/`TitleTextColor`, `HeaderFontSize`/`HeaderTextColor`, and `FontSize`/`TextColor` for body text. Defaults are IBM Plex Sans, 10/8/9 pt, and RGB 220/220/220 for titles/body versus 175/175/175 for headers. `MutedColor` remains available for secondary information. `AccentColor` defaults to 137/190/250; `AccentColor2` defaults to 181/161/226 for secondary actions. Utility metric colors and `GoodColor`/`WarningColor`/`DangerColor` preserve their semantic roles rather than following general text/accent changes.

Surface variables are `BackgroundColor`, `BorderColor`, `BorderThickness`, `DividerColor`, `DividerThickness`, `TableHeaderBorderColor`, `TableHeaderBorderThickness`, `DataBarThickness`, `TrackColor`, `PanelPadding` and `CornerRadius`; graph background/grid/height retain their separate variables. `StylePanel` draws its border inside the panel using the configured thickness times Scale. `StyleRule` uses divider color and thickness times Scale. `StyleTableHeaderRule` uses the independent table-header border color and thickness, defaulting to `50,50,50,255` and 1 logical px. Thickness zero hides the corresponding stroke. CPU thread/process header underlines use these table-header keys with local geometry; their footer lines remain section dividers. Global Settings uses the shared header style beneath its Panel style and Text settings column headings. Scalar utilization, capacity and progress bars use `DataBarThicknessPx=(Max(1,Round(#DataBarThickness#*#Scale#)))` from shared geometry; the default is 6 logical px, matching CPU bars. Modules reserve clearance through the supported 1–12 px range without changing collection cadence. Graph frames, grids, telemetry traces and equalizer band geometry keep their separate styling.

Shared styles are `StyleBounds` (Image), `StylePanel` (Shape), `StyleTitle`, `StyleHeader`, `StyleLabel`, `StyleValue`, `StyleButton` (String), `StyleRule` and `StyleGraph` (Shape). Use `StyleTitle` for panel titles, `StyleHeader` for section/table headings, and body styles for labels and live values. `StyleSecondaryButton` is a color-only override layered after `StyleButton` for Accent 2. Every actual meter must declare `Meter=<type>` as well as `MeterStyle=<style>`. Styles contain no Meter key so they do not draw independently. Set meter-specific X/Y/W/H after applying the style when appropriate, and remove local font overrides that would bypass the intended typography role. Parallax ships no tooltips (removed suite-wide 2026-10-18 for load cost and the owner's preference). Put needed explanations in visible text or docs; `tools/Test-Parallax.ps1` rejects any ToolTip option, bang-set tooltip or dialog tooltip. Statuses must use text as well as color.

Value text in independent utility settings panels uses the body `TextColor`, including clickable values, toggles, numeric values and available choices. Being clickable does not make a setting value an accent-colored action. Command/navigation buttons retain their action colors; swatches and semantic diagnostic/disabled states keep their own roles. This color mapping does not change a panel's existing font sizes, geometry or user preferences.

Independent utility settings panels include `@Resources/UtilitySettingsNote.inc` after their background panel meters. Set the local `SettingsUtilityName` before geometry. Its two compact lines identify the utility and link to `Parallax\Settings`, `Settings.ini`, without saving settings or refreshing utilities. The note occupies logical Y=32–68 relative to Inset; reserve this area below the title and keep settings controls below it. Text uses body size minus 1 pt, body color for context and Accent 1 for the navigation link. It adds no measures or polling.

Global Settings and ColorPicker deliberately retain neutral control text while global text colors are edited. Global Settings form labels/values and table column labels use fixed 9/8 pt editor sizes scaled with the suite; its section names use Accent 1 and its main title still inherits title typography. Independent utility section names also use Accent 1 with HeaderFontSize. ColorPicker keeps neutral text colors and an opaque neutral surface/border, while its fonts still inherit suite typography. These editor exceptions do not replace module appearance overrides. Module layouts must honor the supported global size ranges without silently capping them locally.

## Data and update policy

Default `MetricsInterval=1000` ms, `SensorInterval=2000` ms, `CapacityInterval=30000` ms. These are targets for native measures whose cadence can be controlled. Use UpdateDivider for slow data; static metadata updates on refresh. UsageMonitor has independent 1 Hz workers per category; slowing skin updates does not reduce those workers. Optional categories/skins must be unloaded to remove that cost.

Keep the standalone visualizer in a separate config, default `VisualizerInterval=50` ms (20 FPS), optional 33/100 ms. It captures mixed output-device audio, not solely Spotify. Media's opt-in spectrum drawer creates its own AudioLevel capture only while expanded and live, and runs on Media's existing 50 ms tick (every other tick for the 100 ms choice; 33 ms is not honored there); no other skin's cadence changes. Since 2026-10-23 that capture is leased: it is released after 2 minutes of silence while the [input-idle coordinator](#input-idle-coordinator) reports you away and no WebNowPlaying player is playing, and the drawer defers to a loaded standalone Visualizer, so at most one capture runs (see [Media's capture lease](modules/Media.md#capture-lease)). The standalone itself captures whenever it is loaded. Never run all skins at visualizer frequency. Low power settings do not claim to throttle third-party provider polling. No timer writes every second; save state at user actions/checkpoints as needed.

No provider means unavailable, not measured zero. Distinguish disconnected, stale, unsupported and valid data when the provider exposes enough evidence. Sample timestamps/labels where available; do not invent freshness detection a provider cannot support. Document unavoidable ambiguities.

## Input-idle coordinator

`Parallax\Idle\Idle.ini` (added 2026-10-23, performance phase C; [T6](PERFORMANCE-REVIEW.md#t6-no-stand-down-when-idle-or-the-display-is-off-high)) is a hidden config that holds the suite's only SysInfo `IDLE_TIME` measure: seconds since the last keyboard or mouse input (`GetLastInputInfo`). It lives in its own config because Rainmeter 4.5.28 reads the network interface table (`GetIfTable2`, throttled to once per 250 ms process-wide) before every update of a skin that holds any SysInfo measure, and for every `!UpdateMeasure` of one (`Skin.cpp` `Update` and `UpdateMeasure`): about 2 ms and 30 UI-thread context switches per reading here. Since phase C3 (2026-10-23) its skin never runs Rainmeter's own update (`Update=-1`): `Coordinator.lua` ticks every 2 s through a self-rearming `[!Delay]` chain and updates the measure only when a reading could change the state (Reads, below). No other skin may host a SysInfo measure for this purpose.

- **Lifecycle.** It is not a utility and not a Welcome row. A skin that needs it joins through `@Resources/Idle/Link.lua`; the coordinator re-checks every 300 ticks (about 10 minutes), or at the next tick after a consumer's silent request, whether anything still needs it, and otherwise runs `!DeactivateConfig` on itself, never inside a load. The need is read from files only, and there are two consumers. The drawer's capture lease (C1) needs it while `Parallax\Media` runs `Media.ini` with its spectrum drawer open and not deferred to the standalone Audio Visualizer. The [idle stand-down](#idle-stand-down) (C2) needs it while Idle pause is on and any utility config (Chronometer, CPU, GPU, RAM, IO, Network, Media including Setup and Queue, or Visualizer) is loaded. It appears in Manage Rainmeter like any config. First load writes `StartHidden=1`, `ClickThrough=1` and `Draggable=0`; its only meter is one transparent pixel that never updates, so the config never repaints.
- **Protocol.** `!SetVariableGroup` sets `ParallaxIdleAway` (0/1, idle at least 300 s), `ParallaxIdlePaused` (0/1, idle at least the Global Settings *Idle pause* minutes: `IdlePauseMinutes` 5, 10 or 30; always 0 while that setting is Off or holds any other value), `ParallaxIdleBeat` (`os.time()`) and `ParallaxIdleSync=1` on the `Parallax` group, then `!UpdateMeasureGroup ParallaxIdleHook *` forces each consumer's hook measure. It broadcasts on a change, about once a minute as a heartbeat, after a tick gap over 10 s (sleep or resume), when it starts (from `OnRefreshAction`) and when a consumer asks. While away or paused, input is seen at the next tick, within 2 s. The 32-bit `IDLE_TIME` wrap after 49.7 days of uptime is reduced modulo 4,294,967.296 s, with values within 2 s of a whole step read as 0, so the error stays under a second.
- **Reads.** A tick reads the measure while away or paused (so input is seen at the next tick), at start, on every heartbeat tick and after a tick gap. Otherwise it skips the reading while the last reading, plus the time since (the larger of the `os.time()` and `os.clock()` differences), plus 3 s for rounding, is still short of the nearest threshold (away, or the Idle pause): idle time can only grow by the time that passed, so the broadcasts are the ones a reading on every tick would send, on the same ticks. While you are at the computer that is one reading a minute instead of thirty. Each tick arms the next one first and carries the token of the `Start` that began the chain, so a script error cannot end the chain and a delayed tick left by an earlier load is dropped (Rainmeter keeps delayed commands across a refresh). A test idle file is read on every tick; the measure still follows the real schedule, so a test run costs what a real one does.
- **Cost (measured 2026-10-23: isolated instances, live preferences, hardware rendering, interleaved trials).** Most of what the coordinator costs is its window, not its reading. Every Rainmeter skin owns a DXGI swap chain. Once a second skin window exists, each message any skin processes makes one more call into win32k (`CallNextHookEx` from `dxgi.dll` inside `GetMessage`). That call appears in user-mode stacks only from the second window on, which points to a DXGI message hook; why the hook appears only then is not known. On the owner's PC those calls block on a win32k lock, most likely the session's USER lock, two to three times per message, and each block is a UI-thread wakeup. The probable holder is a TextInputHost then running at about 90% of a core; that is not proven. So a hidden 1x1 skin with no measures adds about 57 wakeups/s beside Media's open drawer (a second and a third such skin about as much again each, one trial each), about 31 beside the 1 s CPU meter and about 15 on its own, whether it ticks or not, hidden or shown, with software or hardware rendering (3 trials each). That part is irreducible in Rainmeter 4.5.28 while the coordinator is a separate config. The reading schedule removes the rest while you are at the computer: with a test idle file of 0, Media's open drawer went from about 175 to 162 wakeups/s (102 without the coordinator) and CPU with Idle pause on from 92 to 78 (47 without); medians of the runs Windows display re-detection left undisturbed, 2 to 5 of 6 per variant. While you are away it reads every tick, as before (Media's open drawer about 175-177 wakeups/s either way). CPU time stays within noise (Media 1.4-2.7%, CPU 3.5-4.3% of a core in all three).
- **Joining.** A consumer defines `ParallaxIdleJoinAction=[!Delay 100][!UpdateMeasureGroup ParallaxIdleJoin]`, appends `#ParallaxIdleJoinAction#` to `OnRefreshAction`, and joins only after its load's own first update. Rainmeter's startup walk loads configs in order, so an immediate join from a skin that loads before `Parallax\Idle` would either ask a coordinator that does not exist yet or activate it twice (a log warning). `Link.join()` does nothing if `Idle\Idle.ini` is missing (an activation would open a modal) or `Rainmeter.ini` is unreadable; sends the silent group request `!UpdateMeasureGroup ParallaxIdleSyncRequest *` when `Rainmeter.ini` records the coordinator active; otherwise `!ActivateConfig "Parallax\Idle" "Idle.ini"`, which runs the coordinator's first broadcast inside that call. Joins are limited to one per consumer load plus one per 10 minutes. Consumers never send `!CommandMeasure` into `Parallax\Idle` (a warning when it is not active) and ignore the state until `ParallaxIdleSync=1`. A consumer that hears no beat for 3 minutes, or no sync 10 s after a load that persisted a parked state, falls back to its live behaviour.
- **Unload.** `OnCloseAction` broadcasts away and paused as 0 only when `Rainmeter.ini` already records `Active=0` (a real unload); at Rainmeter exit and game-mode unload nothing is sent.
- **Test hooks.** `ParallaxIdleTick` (milliseconds, clamped to 500-10000), `ParallaxIdleTestFile`, `ParallaxIdleTestAwaySeconds`, `ParallaxIdleTestPauseSeconds` (1-1800, only while Idle pause is on), `ParallaxIdleTestHeartbeatTicks` and `ParallaxIdleTestReevaluateTicks` are empty or default in the shipped file and honoured only inside their bounds. `@Resources/Idle/tests/` holds `CoordinatorSuite.lua` (offline, also run inside Rainmeter; it checks the reading schedule against a reader that reads on every tick, on randomized input traces with fractional time, flooring, timer jitter, sleeps and clock steps, plus the `os.clock()` bound and the tick chain's tokens) and `Test-IdleCoordinator.ps1` (isolated native runs: transitions within one tick, heartbeats, startup order in both directions with no warning, self-unload with no consumer, invisible window).
- **Limits.** `IDLE_TIME` counts keyboard and mouse input in this Windows session only: gamepad play, video playback and some remote tools do not count.

## Idle stand-down

Global Settings **Idle pause** (`IdlePauseMinutes` 0, 5, 10 or 30; default 0, Off; added 2026-10-23, performance phase C2, owner decision 2) pauses the utilities after that many minutes without keyboard or mouse input and resumes them on the first input. The signal is the [input-idle coordinator](#input-idle-coordinator)'s `ParallaxIdlePaused`.

- **Loading.** Every utility entrypoint (Chronometer, CPU, GPU, RAM, IO-Disk, Network, Media, Media Setup, Media Queue, Visualizer) ends with `[ParallaxIdleHookInclude] @Include99=#@#Idle\Hook#IdlePauseMinutes#.inc` as its last section and appends `#ParallaxIdleJoinAction#` (empty in `Defaults.inc`) to `OnRefreshAction`. `Hook0.inc` is comment-only, so Off loads nothing and changes nothing. `Hook5/10/30.inc` set the delayed join (`[!Delay 100]` and again at 10.6 s) and include `Hook.inc`: the coordinator variables, `MeasureParallaxStandDown` (`StandDown.lua`, groups `ParallaxIdleHook | ParallaxIdleJoin`, never paused, about one run a minute from `ParallaxIdleHookMs`) and `MeterParallaxPaused` ("Paused (idle)" in `MutedColor`, no fill, hidden, divider -1, drawn last). Each entrypoint, after its includes, sets `ParallaxIdleControllers`, `ParallaxIdleHookDivider`, the line's placement (`ParallaxPausedX/Y/W/H/Align`), the headline meters the line replaces (`ParallaxIdleHeadline`) and any gear/value hover pair (`ParallaxIdleHoverSwap`).
- **Headline.** While paused the headline is hidden, never merely covered: the line has no fill, because Global Settings *Background transparency* makes `BackgroundColor` translucent and a covered value shows through. `ParallaxIdleHeadline` lists every meter in the line's row plus the headline values (`test_idle_freeze_contract.py` checks the row and that every name exists). Enter records each listed meter's visibility (its `Hidden` option, which `!ShowMeter` and `!HideMeter` keep current; an INI formula is evaluated) and hides it; leave puts each back as it was. In the title-row skins (CPU, GPU, IO, RAM, Chronometer) the line takes the title's place after the icon, left-aligned and ending before the gear slot, so the gear keeps following the hover while paused. For a gear/value pair (`MeterOptions|MeterTotal` and the like) the hover-out action ends with `#ParallaxIdleHoverAction#[!Redraw]` (empty while Off; with the hook, `Hover()` re-hides the frozen value), RAM's script hover checks the line itself, and on leave the value follows the gear when a hover moved it during the pause, as the skin's own swap would have.
- **Groups (the freeze contract).** `ParallaxIdleFreeze`: every meter that can repaint, meaning a static divider of 0 or more, or a divider set at runtime by a static `!SetOption` or by module Lua (CPU's 320 Thread slot meters, IO's 208 drive-row meters, Media's player icon). Meters only. `ParallaxIdlePause`: every periodic measure except the hook, join and lease members, RunCommand hosts and `MeasureMediaLifecycle`. `tools/tests/test_idle_freeze_contract.py` resolves every entrypoint and variant like Rainmeter and checks these rules, the entrypoint wiring, the Lua divider owners and that shipped state files are all zero; `--list` feeds the native probe.
- **In place** (all utilities except below). Enter: controllers' `IdleEnter`, `!PauseMeasureGroup ParallaxIdlePause`, `!SetOptionGroup ParallaxIdleFreeze UpdateDivider -1` with one forced `!UpdateMeterGroup`, the headline meters hidden, then the line and one `!Redraw`. The skin then repaints nothing: Rainmeter repaints only when a meter's divider elapses, and none does. Leave: unpause, `IdleLeave`, a forced `!UpdateMeasureGroup ParallaxIdlePause` so values are fresh before anything shows, `!SetOptionGroup ParallaxIdleFreeze UpdateDivider ""` (the key is deleted, so the style or skin default applies again), `ReapplyDividers` (each module re-sets the dividers it manages, idle ones at -1, bypassing its caches), one forced meter pass, the line hidden, the headline meters restored, the controllers' optional `RestoreHeadline`, one `!Redraw`. Paints happen only in enter and leave (XMOD-04).
- **Refresh standby** (`ParallaxIdleStandbyMode=refresh`: Media.ini and the standalone Visualizer). When the wanted level differs from the one the load was built with, one request to the module's single writer (`MediaOptions.IdleStandby`, `Companion.IdleStandby`), which saves `MediaStandby` / `VisualizerStandby` in a shipped runtime file and reloads once; the standby load runs at a 1 s tick with no AudioLevel or Win7Audio measure (Media parks an open drawer in the same write), then freezes in place. Input reloads it back. The writer sets `ParallaxIdleStandbyPending=1` once this load's reload is posted (the hook reads it right after the request and asks nothing more while it is pending). If no reload is posted (unreadable state file, failed read-back, nothing to change), a standby load frozen in place leaves in place at once, so it never stays frozen while the user is active (it stays the standby variant, live at its 1 s tick), and the request is retried at most every 30 s.
- **Never trusted blindly.** Nothing happens before the coordinator syncs the load. A beat older than 3 minutes counts as no coordinator: the skin leaves (fails live) and re-joins, rate-limited; a gap in the hook's own schedule (sleep) re-arms the clock instead. A standby load with no sync 10 s after loading fails live. A standby saved while the pause is Off or Custom is cleared at the next load by the module (Media's first options update, the Visualizer's `Announce`). A broadcast that re-enters during a join or a controller call is deferred and re-run, never dropped: the hook runs at most three passes in one update, and a re-entry during the third arms one `[!Delay 100][!UpdateMeasureGroup ParallaxIdleHook]` (at most three in a row) instead.
- **Per module** (details in each module document's Idle pause section): Chronometer hides its clock face and date while paused (a frozen time reads as current) and marks deadlines that passed while paused done on resume; Network hides its IN and OUT rates; CPU re-applies its 64 Thread slots and restarts History; GPU and RAM stop their resident helper hosts at the pause (lease removed, a launch in progress killed, no failure counted) and start one fresh host on resume (readings show Checking... until it samples), and restart their History covers; IO re-applies its drive rows and its history shows the paused time as a gap; Network's own gap handling restarts history and shows sampling... for two ticks; Media and the Visualizer reload as above; Setup and Queue freeze in place.
- **What keeps running while paused.** Each skin's timer (its update now skips paused measures and frozen meters), Rainmeter's mouse timer, the hook's check about once a minute, the coordinator's 2 s tick, which reads `IDLE_TIME` (and so the network table, about 2 ms here) on every tick while paused, and its hidden window (see the coordinator's Cost), UsageMonitor's process-wide category readers (they stop only when no measure of their category is loaded), Network's own per-tick interface-table read and dynamic option re-reads, Media's 1 s tick with the WebNowPlaying plugin thread and its Source and Queue helpers. A deeper stand-down that unloads those readers is a possible later option.
- **Known issue.** RAM and GPU kill a helper launch still in progress at the pause; within a few milliseconds of the launch RunCommand has no process yet, logs `Error 102` and the launch carries on (seen once in five isolated RAM runs; details in RAM.md). Not fixed in C2.
- **Limits.** `IDLE_TIME` counts keyboard and mouse input only: gamepad play, watching video or some remote tools can let the pause start; input on the lock screen and physical input are not covered by the native tests (they use the coordinator's test idle file).
- **Tests.** `@Resources/Idle/tests/StandDownSuite.lua` (offline and inside Rainmeter), `DividerProbe.lua` (staged only) and `Test-IdleStandDown.ps1` (isolated native runs per skin: enter and leave latency, every meter at -1 while paused and back to its snapshot after, paused values constant, reload while paused, watchdog, helper host cycles for RAM and GPU, refresh counts, ticks and render sessions for Media and the Visualizer, captures at 220/1 and 180/0.75 with fonts 12/10/10). Its `-Combined` mode loads the nine utility configs at once (Media.ini; Setup shares that config and runs alone) with the coordinator and checks the same freeze, restore, host and render-session rules plus one coordinator load and exactly two reloads each for Media and the Visualizer. 2026-10-23, both startup orders (coordinator started by the first join, and active from the start), 83 checks each, no log error or warning: every skin paused within 1.7 s and resumed within 2.4 s of the idle write at the 0.5 s test tick (2.6 s in an earlier run whose only failure was the single-skin bound). One Rainmeter thread runs every transition, so the resume blocks it about 1.0 to 1.2 s beyond a normal tick with all nine loaded (both standby reloads included) and about 0.6 s with the seven in-place skins alone; entering blocks nothing measurable. On the owner's 2 s coordinator tick a resume therefore shows within about 2 s plus that block. Physical input, gamepad and video, input on the lock screen, the live cost of the helper relaunches and every performance effect remain unmeasured.
