# Dependencies by utility

Each utility's dependency table is maintained beside its implementation documentation. Update it whenever a runtime, plugin, helper, service or bundled asset requirement changes. The table must distinguish required, bundled and optional components, state which feature uses them, and explain the behavior when they are unavailable. Planned integrations are listed separately. These lists describe the current source; they do not install or provision anything.

## Shared requirements

| Component | Classification | Purpose and availability |
| --- | --- | --- |
| Windows 10/11 and Rainmeter 4.5.26 or newer | Required platform; separately installed | Current suite target. `packaging/release.json` records the package minimums as Rainmeter 4.5.26 and Windows 10.0 (Windows 10 and 11); individual native checks do not certify every OS/version combination. |
| Rainmeter's Lua runtime, native measures/meters and standard plugins | Supplied by Rainmeter | Use the host's built-in facilities. A module table identifies which standard plugins it uses; these are not additional plugin downloads. |
| Parallax shared includes, scripts and `User/*.inc` files | Bundled source | Shared styles, geometry, defaults and saved preferences. Settings that persist changes need write access to their corresponding user include. |
| IBM Plex Sans Regular, Medium, SemiBold and Bold | Bundled asset; SIL Open Font License 1.1 | Loaded privately from the skin's Fonts directory. No system font installation. Shared numeric entry uses Windows Segoe UI. |
| Optional external plugins/providers/services | Feature-specific; see each utility | Never a blanket requirement for the suite. Distinguish a plugin bundled with Rainmeter, a third-party plugin bundled in the Parallax `.rmskin`, and a separately installed component. Missing provider behavior and explicit setup belong in the utility list. |
| Input-idle coordinator `Parallax\Idle` (`Idle/Idle.ini`, `@Resources/Idle/Coordinator.lua`, `@Resources/Idle/Link.lua`) | Bundled source; optional, loaded on demand | The suite's one input-idle signal, for features that act while you are away. Uses Rainmeter's built-in SysInfo `IDLE_TIME` (Windows `GetLastInputInfo`: keyboard and mouse only) on a 2-second tick, read on every tick while you are away or paused and about once a minute otherwise. Side effects: every SysInfo update makes Rainmeter read the network interface table (`GetIfTable2`, about 2 ms here), which is why only this config hosts it and why its skin never runs Rainmeter's own update; and its hidden window adds a DXGI message hook to Rainmeter's UI thread, about 57 wakeups/s beside Media's open drawer and 31 beside the CPU meter on the owner's PC (CPU time within noise). Loaded only while a consumer needs it and unloads itself otherwise; it adds no process, plugin, installation or file write. Without it (missing or unloaded) consumers keep their live behaviour. See [ARCHITECTURE.md](ARCHITECTURE.md#input-idle-coordinator). |
| Idle stand-down hook (`@Resources/Idle/Hook0/5/10/30.inc`, `Hook.inc`, `StandDown.lua`) | Bundled source; optional, Global Settings Idle pause (default Off) | Loaded by every utility only while Idle pause is 5, 10 or 30 minutes; pauses the utility after that long without keyboard or mouse input through the input-idle coordinator above. Off loads a comment-only include. Each utility's Dependencies row records what it stops, restarts and keeps running ([shared design](ARCHITECTURE.md#idle-stand-down)). |
| Automatic update check hook (`@Resources/Update/Hook0.inc`, `Hook1.inc`, `Update.lua`, `Feed.inc`, `State.inc`) | Bundled source; optional, Global Settings **Updates** > **Auto check** (default Daily) | Loaded by every utility while Auto check is Daily: one Script measure (runs at load, then an hourly `[!Delay]` look) and a WebParser that is disabled except during a request. About once a day the first utility to find a check due makes one request for the release feed on github.com (`releases/latest/download/parallax-update.json`, not the rate-limited REST API) and saves the result in `State.inc`; a newer release opens the `Parallax\Update` prompt. No meter, process, plugin or installation; failures are recorded and retried after an hour. Off loads a comment-only include and contacts nothing. See [UPDATES.md](UPDATES.md). |
| WebNowPlaying plugin 2.0.7.0 | Bundled third-party plugin; MIT License | Installed by the `.rmskin` into the Rainmeter Plugins folder unless a newer version exists, for Media's optional playback view; see [Media](modules/Media.md#dependencies) and the [bundled plugin notes](../packaging/Plugins/WebNowPlaying/README.md). Its browser extension and desktop adapters are separate installs. |

Bundled attribution is recorded in [`@Resources/Licenses/NOTICE.txt`](../Skins/Parallax/@Resources/Licenses/NOTICE.txt), with font and module-local license files. Bundled helper source does not imply that an external executable, plugin, account, credential, driver or service is included. Machine-specific sensor mappings and private runtime data are excluded from distribution.

Provider behavior and integration constraints are detailed in [PROVIDERS.md](PROVIDERS.md). Build and release tooling requirements are separate from utility runtime requirements; see [PACKAGING.md](PACKAGING.md). The update check (WebParser: daily from the loaded utilities, when Global Settings opens and on Check now; plus the one-shot `UpdateInstall.ps1` helper on Update) is optional and described in [UPDATES.md](UPDATES.md); it moved from the Welcome panel to Global Settings on 2026-10-26. Dependency tables should record only versions or constraints supported by the source and evidence, rather than guessing a minimum or claiming compatibility with an untested latest version.

Since 2026-10-27 Media's shuffle and repeat toggles use four more player types and two commands of the already bundled WebNowPlaying plugin. Clicking a Spotify queue row or **Refresh** runs one short hidden `QueueProvider.ps1` request on a dormant RunCommand host (Media.ini's `Queue/QueueControlHost.inc`, or Queue.ini's existing one) that hands the request to the running worker and exits. Skipping to a row uses the optional Spotify permission `user-modify-playback-state`, now requested at sign-in, and Spotify's skip endpoint, which needs Premium and an active device. A read-only grant keeps reading the queue with unclickable rows. No new plugin, package, process type or polling. See [Media's dependency list](modules/Media.md#dependencies) and [row clicks](modules/Media.md#row-clicks-and-refresh-2026-10-27).

Media's restart recovery reuses its bundled Lua controller, existing Windows PowerShell 5.1 provider helpers and their Windows APIs. It adds no installed dependency or OS startup entry. A normal Rainmeter view load can resume only explicitly enabled providers; private intent/launch files are runtime state and never distribution assets. Settings and isolated/custom profiles do not perform automatic recovery. See [Media's dependency list](modules/Media.md#dependencies) and [recovery contract](modules/Media.md#provider-recovery-after-restart).

Disk Meter's eject icon (removable and optical drives only) reuses Rainmeter's bundled RunCommand and Windows PowerShell 5.1: one hidden one-shot process per click runs the bundled `Eject.ps1`, which sends the taskbar's device-eject request for a removable drive or opens an optical tray. It adds no installed dependency, polling or elevation; see [IO dependencies](modules/IO.md#dependencies).

Disk Meter's per-drive overlay color box (in its settings utility) likewise reuses RunCommand, Windows PowerShell 5.1 and WinForms: one hidden one-shot process per click runs the bundled `DriveColorInput.ps1`, which only validates a `#RRGGBB` entry and writes nothing. It adds no installed dependency or polling; see [IO dependencies](modules/IO.md#dependencies).

Network's Wi-Fi band line reuses RunCommand with the inbox `netsh.exe` (`wlan show interfaces`, hidden): one launch each time a Wi-Fi connection's SSID or protocol changes, none on a wired-only link and no timer. Without a `Band` line in its output (before Windows 11 24H2, or a non-English label) the line reads `Band: unavailable`. See [Network dependencies](modules/Network.md#dependencies).

GPU's per-application memory rows reuse Rainmeter's bundled UsageMonitor plugin and the Windows `GPU Process Memory / Local Usage` counter. Five exact named measures share one additional in-process category worker at UsageMonitor's independent one-second cadence. Since 2026-10-23 they load only while the process table and its VRAM column are shown (`GPUShowProcesses=1` and `GPUShowProcessMemory=1`); with `GPUShowProcesses=0`, GPU Meter does not load UsageMonitor at all. They add no external installation, helper process, driver, session file or protocol change. Missing, unsupported and ambiguous zero observations display `--` in the process table's VRAM column; see the [GPU dependency list](modules/GPU.md#dependencies). GPU process names for processes that refuse a handle to a non-elevated Rainmeter (such as dwm, csrss and System) come from ntdll's documented `NtQuerySystemInformation`, called by the existing helper; this adds no process, plugin or installation. Without one selected discrete GPU, that same Windows PowerShell helper host now also runs, for process names only; see the [GPU dependency list](modules/GPU.md#dependencies).

Visualizer's current renderer uses Rainmeter's native Shape paths, Container compositing and LinearGradient fills for the 24 measured bands. Color selection and the compilation of the band paths to literal geometry (`SpectrumPaths.lua`) run only on load; the dynamic mask then re-reads only each band's height. Its cost in Media's drawer is measured in [PERFORMANCE.md](PERFORMANCE.md#spectrum-drawer-path-cost-2026-10-11). The current-output icon is a native Shape adaptation of the bundled user-supplied Lucide Speaker SVG; its source, provenance and ISC license ship under the module's `Icons/Lucide/` directory, with no SVG runtime loader. Rainmeter's bundled Win7Audio plugin supplies the read-only default-output volume and event-only `TogglePrevious`/`ToggleNext` device commands; switching adds no additional capture parent or polling. This adds no external package, plugin, helper, service, installation or polling launch. AudioLevel, bundled typography and the explicit-action shared numeric helper retain their documented roles. Since 2026-10-23 the bundled, event-only `Modules/Visualizer/Companion.lua` reads Rainmeter.ini through the shared `@Resources/Idle/Link.lua` reader after each load and after a real unload, and tells Media's open drawer to defer to or reclaim the capture (two silent group bangs; no process, polling or file write); see the [Visualizer dependency list](modules/Visualizer.md#dependencies).

Media's spectrum drawer reuses Rainmeter's bundled AudioLevel plugin and the Visualizer module's shared variable, capture and spectrum includes. Its capture parent exists only while the drawer is open (`VisualizerDrawer=2`); collapsed, hidden and Setup views load no AudioLevel measure. Since 2026-10-11 the open drawer also hosts the standalone's output row (`Audio.inc`): one bundled Win7Audio measure for the read-only output volume and the event-only `ToggleNext`/`TogglePrevious` device switch, and two more AudioLevel children (device name, device list) of the same parent — again only while open. Media settings now includes Audio settings' shared steppers (`SettingsShared.inc` and the Visualizer `Settings.lua`), adding no plugin beyond their dormant, click-only numeric-input host. Opening runs on Media's existing 50 ms tick, so no other skin's cadence changes. To keep its panel still while the window grows upward, Media writes `AnchorY` and a `ParallaxDrawerAnchorY` record in its own Rainmeter.ini section on drawer clicks, Media settings saves and any load whose drawer-owned anchor does not match (the load-time `!SetAnchor` also rewrites `AnchorX` with its existing value); it never changes an anchor the user set, and it adds no installation, helper, process or polling. Since 2026-10-23 the drawer defers to a loaded standalone Visualizer instead of running a second capture (the standalone's event-only `Companion.lua` tells Media to re-check through two silent group bangs, reading Rainmeter.ini with the shared `@Resources/Idle/Link.lua`), and the open drawer's capture lease releases that capture after 2 minutes of silence while you have been away 5 minutes and no WebNowPlaying player is playing, using the input-idle coordinator `Parallax\Idle` (above) and the bundled runtime file `Modules/Media/CaptureState.inc`; without the coordinator the drawer stays live. See [Media's dependency list](modules/Media.md#dependencies), [the spectrum drawer](modules/Media.md#spectrum-drawer) and [its capture lease](modules/Media.md#capture-lease).

RAM's resident PAGE host and GPU's resident telemetry host run detached from RunCommand since 2026-10-23 (performance package B1). For each, one short hidden RunCommand launcher (plain Windows PowerShell 5.1, no compile) mints the session with `[guid]::NewGuid()`, starts the host with `Start-Process -WindowStyle Hidden` and exits, so RunCommand no longer owns or kills it and no separate compiling session bootstrap runs. The hosts still use only the existing Windows PowerShell 5.1/.NET runtime and add no installed dependency; each stops on its session lease, its retained Rainmeter process handle, or the skin removing the lease on close. Since 2026-10-25 each launcher also writes its session token to a per-skin owner file in TEMP, so a refresh (which runs no close action) or a close stops the previous session at once rather than at its lease lapse. See [RAM](modules/RAM.md#live-memory-semantics-and-units) and [GPU](modules/GPU.md#direct-gpu-temperature).
