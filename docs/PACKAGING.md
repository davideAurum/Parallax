# Packaging Parallax

The repository stages release inputs and builds the distributable `.rmskin` itself. `tools\Package-Parallax.ps1` writes the same format as Rainmeter's Skin Packager: a deflate ZIP with `RMSKIN.ini` in its root, followed by the 16-byte `RMSKIN` trailer that Skin Installer checks before it accepts a package. Renaming a plain ZIP is insufficient. The official **Manage Rainmeter > Create .rmskin package** dialog remains a valid alternative for the same staged `Skins\Parallax` root; Packager accepts a source outside an installed Skins directory. See the [official distribution guide](https://github.com/rainmeter/rainmeter-docs/blob/master/source/manual/distributing-skins/index.html) and the installer source (`Library/DialogInstall.cpp` and `Library/DialogPackage.cpp` in the [Rainmeter repository](https://github.com/rainmeter/rainmeter)), which the packaging and verification tools follow.

## Validate and stage

From the repository root, using PowerShell 5.1 or later:

```powershell
.\tools\Test-Parallax.ps1 -RequireAllModules
.\tools\Stage-Parallax.ps1 -Version '0.1.0-alpha' -RequireAllModules
.\tools\Package-Parallax.ps1
```

The validator permits modules to arrive independently, warning for missing utilities. Once all required entrypoints are ready, use `-RequireAllModules` on the validator and the stage. `-WarningsAsErrors` is available on the validator after every warning has been reviewed. `Package-Parallax.ps1` always stages with `-RequireAllModules`; it takes the version and the other release fields from `packaging\release.json`, so the separate stage command is only needed for a source snapshot without a package. See [Create the .rmskin](#create-the-rmskin).

Run `.\tools\tests\Test-PackagingTools.ps1` after changing the tools. Its isolated fixtures cover layered settings, invalid includes, cycles, local duplicates, absent modules, unknown styles, exclusions, credential-shaped defaults, preservation paths, fresh destinations, and manifest hashes. The packager fixtures build a complete synthetic suite into an `.rmskin`, check the trailer, the UTF-16LE `RMSKIN.ini` fields, forward-slash entry names, manifest hash agreement, the header image size and the `.sha256`/record outputs, and reject a missing author, non-numeric minimum versions, an absent load skin, a wrong-size header, a version that differs from a reused stage, a stage edited after its manifest, an existing package without `-Force`, and packages whose trailer key or length is wrong, including a plain ZIP renamed to `.rmskin`. A synthetic plugin pair (minimal PE headers, never loadable) checks the `Plugins/<arch>/<name>.dll` layout, the package record and `-NoPlugins`, and the fixtures reject a missing 64-bit build, a non-PE file, a 64-bit image in the 32bit folder, a Rainmeter-owned plugin name and an unstaged license. Media queue/source detection, Settings input, CPU/GPU discovery, RAM/GPU metadata, and Chronometer event editor fixtures copy the actual helper/build files as data, verify hashes, and reject similarly named files, repeated text suffixes, private/test copies, and runtime data. They never run or import a helper, read sensor registry exports or media snapshots, query CIM, graphics or native media-session APIs, load the editor assembly, or invoke a compiler. Fixtures remain in a unique system temporary directory for inspection. The package fixture also checks that `parallax-update.json` matches the package hash, tag URL and notes link, and that a version differing from `@Resources\Version.inc` is refused. An exact-path fixture covers `UpdateInstall.ps1`. The full suite passed under Windows PowerShell 5.1 on 2026-09-23, after the fixtures were updated for Welcome as a required component. Test/Tests, QA and Fixtures folders are excluded from staged skins.

Run `python .\tools\tests\test_settings_geometry.py` with Python 3.10+ after changing Settings geometry. It reads the actual shared includes and Settings config, then checks all 100 preset scale/width/gutter combinations for aligned single/double widths, padded button bounds, and nonoverlapping declared text rectangles. It does not render fonts, test mixed Windows DPI, or execute Lua.

Every stage creates a fresh `build\Parallax-<version>-<UTC timestamp>-<random>` directory. It never deletes, replaces, installs, or launches anything. Only files under the source `Skins\Parallax` enter the staged skin root. Repository docs, tools, and packaging metadata remain outside that root.

Review `stage-manifest.json` for included paths, SHA-256 hashes, and exclusions. `variables-files.txt` gives the exact preservation field for this stage. Only skin source, Lua, supported image/audio/font assets, and text documentation are allowed by default. Hidden, private, credential, token, cache, runtime, temporary, and log paths are excluded. Developer and runtime directories are pruned before traversal by both validator and staging; the manifest records excluded directory roots without enumerating their contents. Reparse points in the production tree are rejected. `User` ships only `.inc` files containing clean defaults. A heuristic rejects nonempty credential-shaped INI options without printing their values. These checks cannot detect every secret; inspect release inputs, never stage from a live personalized installation, and keep authentication data outside the distributable tree.

`SourceProvider.ps1` is Media's optional local Windows media-session observer, the fourth exact Media helper exception. Explicit Start enables collection and saves private recovery intent; a later normal Player load can Resume that enabled observer. Resume never enables missing intent or clears Stop. Its fixed built-in Windows APIs inspect local sessions without network, authentication, browser inspection or playback commands. There is no startup task or service. One worker mutex prevents overlapping collectors; a separate control mutex serializes Start, Resume and Stop. Concurrent loads can briefly create competing bootstrap children before one owns the worker mutex, but only one collects. Only explicit Start clears an old Stop marker before launch, so a delayed worker honors a completed Stop. Stop writes its durable marker before disabling intent, waits up to 10 seconds for each mutex (20 seconds of bounded lock waits), and never kills unrelated processes. Closing a skin leaves this explicitly enabled observer running.

Collection runs on a two-second cadence with a four-second asynchronous budget, two consistent metadata reads per session, at most 16 sessions, and no overlapping pending Windows requests. A synchronous Windows API call cannot be forcibly timed out; the passive reader still expires its snapshot six seconds after collection starts. The idle wait checks the stop signal every 100 ms without launching processes. These bounds are not a measured CPU/memory performance result.

## Create the .rmskin

`tools\Package-Parallax.ps1` turns a stage into `dist\Parallax_<version>.rmskin`:

1. Reads `packaging\release.json` (name, author, version, minimum Rainmeter and Windows versions, load skin, header image). Parameters such as `-Version`, `-Author`, `-MinimumWindows`, `-HeaderImage`/`-NoHeaderImage` and `-StageRoot` override it. Author and both minimum versions are mandatory; `mergeSkins` must stay false.
2. Runs `Stage-Parallax.ps1 -RequireAllModules`, or reuses an existing stage passed with `-StageRoot` after checking that its manifest version matches, re-hashing every staged file against `stage-manifest.json` and rejecting unlisted files, reparse points, a missing load skin or unexpected Variables files.
3. Writes `RMSKIN.ini` as UTF-16LE with a byte-order mark, which every Skin Installer version reads: `Name`, `Author`, `Version`, `LoadType=Skin`, `Load`, `VariableFiles` copied verbatim from the stage's `variables-files.txt`, `MinimumRainmeter` and `MinimumWindows`. A copy stays in the stage directory for review.
4. Adds the optional 400x60 `RMSKIN.bmp` header, each bundled plugin listed under `plugins` in `release.json` as `Plugins/32bit/<name>.dll` and `Plugins/64bit/<name>.dll`, then every staged file as `Skins/Parallax/...` with deflate compression, ASCII forward-slash entry names and no directory records, in the order the manifest lists them. A plugin is accepted only when both builds exist, are PE images of their folder's machine type, carry a version resource equal to the declared version (a missing resource is a warning), the name is not one of Rainmeter's own plugins, and the declared license file is part of the stage. `-NoPlugins` omits them.
5. Appends the 16-byte trailer: little-endian int64 archive length, one zero flags byte and `RMSKIN\0`. Skin Installer refuses a file whose recorded length does not match or whose key is absent.
6. Re-reads the finished bytes with `tools\Test-ParallaxPackage.ps1`, which parses the trailer and `RMSKIN.ini`, opens the archive both with and without the trailer in view, checks that the load skin and every Variables file exist as entries, requires both architectures of every plugin entry with the right PE machine type and the expected hashes, and compares each decompressed skin file's size and SHA-256 with the manifest. Only then is the file moved from its `.partial.rmskin` name to the final name.
7. Writes `<package>.sha256` in `sha256sum` format and `<package>.json`, a package record with the metadata, hashes, entry counts, stage path and tooling version.

`Test-ParallaxPackage.ps1 -PackagePath <file.rmskin>` verifies any package on its own, including one produced by the official Skin Packager, and never installs it. `dist\` and `*.rmskin` are ignored by Git; publish the package as a release asset together with its `.sha256`. Packaging still does not install Rainmeter, bundle plugins, write into the live Skins directory, launch Skin Installer or publish releases, and a structurally verified package is not an installation or upgrade test.

## What static validation establishes

The validator checks all `.ini` / `.inc` files for duplicate local sections and options, recursively resolves shipped `@Include*` paths, detects cycles and missing includes, checks the presence of config metadata and meters, verifies simple named measure/style references, and checks resolved Lua script paths. It recognizes `#@#`, `#ROOTCONFIGPATH#`, `#CURRENTPATH#`, and simple defined variables in include paths. Relative include paths are interpreted from the including file's directory. Include keys run in source order, so local keys following an include can override its defaults.

`[Variables]` repeated across different include files is intentional and accepted. Duplicate sections within one physical file are errors. Non-Variables sections layered across files are warnings for review. Rainmeter merges sections across files but ignores a second same-named section within a physical file. See the [official @Include rules](https://github.com/rainmeter/rainmeter-docs/blob/master/source/manual/skins/include-option.html).

This is a conservative linter, not Rainmeter's parser. It does not reproduce every parsing or meter insertion detail, execute Lua, evaluate formulas, validate every bang/plugin option, resolve dynamic section references, inspect binary assets, or prove that the skin renders. Unresolved include paths fail so missing shipped defaults cannot pass unnoticed. Intentional dynamic include designs need a focused validator extension with fixtures. A passing check is never a runtime or performance claim.

## Release gates

- Confirm every planned module is implemented and passes static validation with `-RequireAllModules`; review any remaining warnings.
- Use a separate test installation or disposable profile to load every supported config and variant. Inspect Rainmeter's log, controls, refresh/unload behavior, empty states, and absence of optional providers.
- Verify standard and double widths, snapping gaps, scaling, long labels, monitor boundaries, and mixed-DPI layouts visually.
- Measure idle, active, and visualization-enabled CPU/memory use on recorded hardware. Compare against the same Rainmeter setup without Parallax; record provider processes and sampling intervals separately. No performance result is established yet.
- Verify dependency discovery, supported versions, permission failures, disconnects, recovery, and disabled-provider behavior. Authenticate only in the test environment, then ensure no credentials enter the stage.
- Install the produced `.rmskin` (from `Package-Parallax.ps1` or the official Skin Packager) into a clean test environment. Reinstall/upgrade over changed global and per-module `[Variables]`, including empty values, and verify preservation and new defaults. Runtime state outside `[Variables]` needs a separate migration test.
- Exercise an upgrade from a build with the retired `Parallax\IO\IO.ini` installed and loaded. Confirm the resulting installation contains only `IO-Disk.ini` as the I/O monitor entrypoint, loads it correctly, and preserves supported `User/IO.inc` choices. Source deletion and fresh staging do not establish removal from an existing installation. If Skin Packager retains the retired file, provide and test an explicit migration step limited to that file before release. This remains an upgrade test; development work has not changed live skins.
- Review author credit, license, third-party notices, minimum requirements, release notes, generated Variables files list, and manifest. Resolve `packaging/release.json` placeholders.
- Record the final artifact's SHA-256 and the tested Rainmeter/Windows versions. A stage alone does not satisfy this gate.

The scripts do not install Rainmeter, download or bundle plugins, write into the real Rainmeter skin path, launch Skin Installer or Skin Packager, or publish releases. Installation, upgrade testing and publishing remain explicit release work after validation.
