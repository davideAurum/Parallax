# Unreleased and outstanding

Where things stand between releases: what is on `main` but not yet in a published package, and what is still open. Update this file when work lands. When a release ships, move its "On main" entries into that release's notes and clear them here. Stage goals live in [ROADMAP.md](ROADMAP.md); this file is the short list.

**Latest release:** [0.1.0-alpha.14](https://github.com/davideAurum/Parallax/releases/tag/v0.1.0-alpha.14) (2026-11-23): Media's **Album colors** (with the bundled Chameleon plugin) and queue cover art with Normal and Compact rows, a hover highlight, a Refresh icon and the **Sign in again** header; GPU Meter's integrated-GPU mode; and CPU Meter's `HWiNFO: open Sensors` footer ([Media decision log](superpowers/specs/2026-11-19-media-queue-art-and-album-colors-design.md)). Checks before publishing: `Test-Parallax -RequireAllModules` and `Test-ParallaxPackage` passed; the package carries both Chameleon DLLs at their recorded hashes, libChameleon's license and the new Media files, and no test files. ## On main, not in any release

- **Media's queue follows the player** (2026-11-24). A song the player has reached leaves the queue drawer at once, and the running helper is asked to read again (one extra read per track change, no process) instead of up to 30 s later. The `Song / Artist` heading lines up with the queue's left edge. New snapshot format `PARALLAX_QUEUE_V5`. Verified live at natural track changes; Next, Previous and row clicks are not ([Media.md](modules/Media.md#queue-follows-the-player-2026-11-24)).
- **Album colors reach the queue's artist names and muted covers** (2026-11-24): names and the heading's "Artist" follow the cover; a cover with only a faint tint counts as colored instead of keeping the theme. No muted cover has been seen live yet.
- **Dev mode keeps the helpers' data path** (2026-11-24), so the copy's Media shows the source and queue ([DEVMODE.md](DEVMODE.md)).
- **Media says when a Spotify helper was never started** (2026-11-24). On a machine where Source detection was never started the player title reads `Media Player: detection off` instead of `Unknown` while Spotify (or any generic Windows session) plays, and an opened queue drawer reads `Spotify queue is off: Media settings` instead of being blank. Clicking either opens Media settings. Both helpers stay opt-in, nothing starts by itself, and neither hint returns after a Stop. Details and checks: [Never-started helpers](modules/Media.md#never-started-helpers). Still unverified: physical clicks, dragging the panel by its title, and a real fresh install.

## Open: known gaps and housekeeping

- Before alpha.5, Media's Source/Queue workers could outlive Rainmeter and block upgrades. Copies at alpha.4 or earlier still have this. alpha.5 and later fix it, but the first upgrade from an old copy may need Rainmeter quit and those `powershell.exe` workers ended by hand ([UPDATES.md](UPDATES.md#upgrading-past-running-media-helpers)).
- A Windows PowerShell helper that starts using `Get-FileHash` or a `Microsoft.PowerShell.Security` cmdlet needs the same `PSModulePath` reset as `UpdateInstall.ps1`.
- Three Global Settings test fixtures were stale before developer mode: `Test-ThemeDropdown.ps1`, `Test-SettingsFields.ps1` and `Test-SettingsRefresh.ps1` still expected the 758 px panel and did not stage `Version.inc`, `Update\*` or `Idle\Link.lua`, so none could run since the Idle pause and Updates sections. On 2026-10-28 their file lists and heights were brought up to date; the first two pass, and `Test-SettingsRefresh.ps1` (run it with `powershell.exe`, not PowerShell 7) now stops at "Scale burst: pixels changed outside MeterGeometry/MeterScaleInput (row 761)", a row inside the Updates section that its before/after capture comparison does not allow for. It predates the Developer section (which starts below that row) and is still open.
- Four developer-only native checks that failed or flaked on 0.1.0-alpha.14 were fixed on 2026-11-24 (Rainmeter 4.5.28.3936, each run alone under Windows PowerShell 5.1). Every cause was in a fixture: no product fault was found and no product file changed.
  - `Test-MediaSettings.ps1 -IdentityFocused` still expected neutral song, artist and album icons (Accent 1 since 2026-11-19, [decision C5](superpowers/specs/2026-11-19-media-queue-art-and-album-colors-design.md)) and, hidden behind that, near-black transport glyphs (white since 2026-10-25). It passes 3 of 3 (25 layouts, 6 captures), as do `-IdentityIconsFocused`, `-PlayerNameFocused` and `-PlayerNameIconsFocused`; muted icons, a blank song icon and dark glyphs each make it fail. [Media.md](modules/Media.md) still says in one place that metadata icons use `MutedColor`.
  - `Test-IdleStandDown.ps1 -Skin Media,Setup` loaded album colors without the Chameleon plugin; they are now stubbed, as in the Media harnesses (a one-off run with the real DLL in the isolated instance also passed, 28 of 28). It also compared the spectrum mask's divider with its value before the pause, but that divider follows the output's signal: with music playing it reads 1 before, -1 on the first tick of the resume's reload and 1 again 3 s later. The mask is now checked against the capture state at all three points, which catches a signal action that no longer restores it. The repeats showed a third, intermittent fault: the runner's poll of `CaptureState.inc` locked out Rainmeter's own `!WriteKeyValue`; it now reads shared (polling as fast as possible, the old read fails 3 of 3 and the new one passes 3 of 3). With music playing it then passed 4 of 4 at 220/1; 180/0.75, the standalone Visualizer and a combined Chronometer, Media and Visualizer run passed once each before that last change.
  - `Test-MediaCaptureLease.ps1` stage A judged variant 1 with the PC's real input, so it failed whenever the keyboard or mouse had been used in the last 5 minutes: a paused drawer resumes at the coordinator's first sync, as designed. Its idle input is now staged (56 checks, 0 failures). Stage B needs silent output, because the lease parks only after quiet: the unchanged stage passes 39 of 39 with music playing once a scratch skin's idle floor counts that music as quiet, so sound is the whole cause. It now stops with a `SOUND` line that says so, before the first park or in any later one, and the run ends as not judged instead of failing step after step. Stage C passes (13 checks). Stage B has not been run with really silent output yet.
  - `Test-MediaTransport.ps1` timed out when the runner had the report open as the observer replaced it. The observer now tries again on its next update and reports how often it had to. With the report deliberately held open, the old observer fails 2 of 2 and the new one passes 3 of 3 (16 to 21 retries); 10 of 10 ordinary runs pass (no retry needed).
  - No other harness asserts a delete-and-rename report. `Run-UpdateSmoke.ps1`'s probe deletes and renames without asserting, on every update, and is read only inside the same Rainmeter. Network's `QA/SettingsSmoke.lua` asserts that it can delete the runner's command file, a similar race that has not been seen to fail and was left alone.
- The physical input, provider and wider hardware and display passes now belong to the beta itself ([ROADMAP.md Stage 3](ROADMAP.md#stage-3-beta-020-betan)).
